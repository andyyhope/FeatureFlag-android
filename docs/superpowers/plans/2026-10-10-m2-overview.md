# M2 (Android + bridge + signals): overview and interface contract

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement the two sub-plans below task-by-task, in order (A1→A6, then B1→B4). Steps use checkbox (`- [ ]`) syntax for tracking.
> This file itself is not a task list. It is the **contract** shared by the two M2 sub-plans. Read it before any task. Every sub-plan task implicitly includes the Global Constraints below, and must use **exactly** the names and signatures in the Interface Contract. A task may add private or internal helpers; it may not rename anything here.

**Goal:** Give FeatureFlag's Kotlin core its Android half:
- a `SharedPreferencesSource`;
- `publishSchema(context)`;
- a host-side signal channel;
- a signature-permission ContentProvider bridge, through which a companion app reads the host's schema, reads and writes its overrides, observes changes and sends signals.

**Architecture:**
- **Two new Android library modules.**
  - `featureflag-android` has no manifest components. It holds the source, schema publishing, the signal channel, the shared bridge contract and the companion-side client.
  - `featureflag-bridge` adds only the exported provider, its permission and its manifest entries, so a host opts into exposing itself.
- **No registration API.** The provider finds everything by convention:
  - the schema from the file `publishSchema(context)` writes;
  - the overrides from one well-known preferences file, which the host's pole also reads through `SharedPreferencesSource.companion(context)`;
  - signals from the process-wide `FlagSignalChannel.host`.
- **Core work first.** Core gains a public box ↔ JSON-text codec (`FlagValueJson`), a hardened `FlagSchema.write` and a QR decompression plausibility check before any Android code depends on them.

**Tech Stack:**
- Inherited from M1: Gradle 9.5.1; Kotlin 2.2.10; kotlinx-coroutines 1.10.2; JUnit 4.13.2 + kotlin-test-junit; Turbine 1.2.1; detekt 1.23.8.

## Review Focus

These are the inputs and conditions the spec implies but no single task's happy path exercises. Each is pinned by a named test in the task that owns the code.

1. **A payload larger than a binder transaction.** A `Bundle` crossing processes is limited to about 1 MB. With record lists or data blobs, an override set can grow past that.
   - Both directions are capped at `FlagBridgeContract.MAX_PAYLOAD_BYTES` (512 KiB).
   - Reading: the provider answers `STATUS_TOO_LARGE` instead of throwing `TransactionTooLargeException` in the host.
   - Writing: the client throws `FlagBridgeException.TooLarge` before sending.
   - Pinned by B1 `overridesLargerThanTheLimitAreRefusedNotThrown` and B3 `writingMoreThanTheLimitFailsBeforeSending`.
2. **The store holds a foreign or mistyped value.** The well-known preferences file belongs to the host app, so the host's own code may have written the same key with another type.
   - A type-guided read returns `null`, so resolution falls through.
   - `overrides` leaves the value out instead of failing the whole document.
   - An `apply` overwrites it.
   - Pinned by A4 `aValueStoredWithAnotherTypeReadsAsNothing` and B1 `aStoredValueTheSchemaRejectsIsLeftOutOfOverrides`.
3. **The host never published, or its schema file was deleted.**
   - `connect()` returns `NotPublished`.
   - `overrides` and `apply` answer `STATUS_NOT_PUBLISHED` and do not crash the host.
   - Pinned by B1 `everyMethodAnswersNotPublishedWithoutASchema` and B2 `aHostWithoutASchemaIsNotPublished`.
4. **The host is installed under a suffixed application id** (for example `com.example.app.debug`). The authority and permission come from the package the companion was given. A wrong package yields `HostNotFound`, and its message names the package that was looked for and mentions the suffix. Pinned by B2 `hostNotFoundNamesThePackageAndTheSuffixHint`.
5. **The host process dies mid-session.** A held `FlagBridgeSource` must survive:
   - the next write reacquires a client and succeeds;
   - the `ContentObserver`, which is registered with the system rather than the provider, keeps firing.
   - Pinned by B4 `aSourceSurvivesTheHostProcessDying`.

## Deviations from the spec

The spec is `docs/superpowers/specs/2026-10-08-android-parity-design.md`. Each line names the change and why.

1. **`connect()` has two extra results.**
   - `UsesPermissionMissing`: S6 showed that without `<uses-permission>` the host is invisible, which would otherwise read as `HostNotFound`.
   - `BridgeNotInstalled`: the host is installed but does not include `featureflag-bridge`.
2. **No `<queries>` in the companion manifest.** `<uses-permission>` alone grants visibility (S6). The spec text was already corrected by the S6 commit.
3. **iOS shows one companion failure message, not two.** The message names two causes: the host never ran, or the App Group is missing. Android's finer statuses replace it. The spec's "two failure messages" wording is loose.
4. **The ART number check exercises the public `FlagDefaultComparison.toString()`.** `MessageText` itself is internal to core, and `FlagDefaultComparison` has no `description` property.
5. **`FlagPole.apply(payload)` keeps writing key by key.** The bridge never goes through it: the provider calls `SharedPreferencesSource.setBoxes` directly, which is one commit. Rerouting `apply` would need its undo logic redesigned, for no bridge benefit. This stays a follow-up.
6. **Publishing is verified at M4,** as stated in Global Constraints.
7. **`bridged(ctx)` is `SharedPreferencesSource.companion(context)`.** The spec's "Using it" section names `bridged(ctx)`; the contract renamed it.

## Interface contract

All signatures are public unless they say `internal`. Each heading names the package. "Throws" lists exceptions that escape to callers.

### Core additions (A2, A3; `featureflag-core`)

```kotlin
// package com.andyyhope.featureflag.values
/** One box as JSON value text, using the same rules as export/import, so a store or a wire can carry any flag type. */
public object FlagValueJson {
    /** Compact JSON value text: `true`, `3`, `0.10000000000000001`, `"2026-01-01T00:00:00Z"`, `[1,2]`, `{"a":"b"}`.
     *  Same rules as FlagValueBox.toJson() + JsonWriter.compact. Throws FlagSerializationException.NonFiniteNumber(null). */
    public fun encode(box: FlagValueBox): String
    /** The box [text] holds as [type], or null when it is not valid JSON or not that type (strict, as JsonValue.toBox). A top-level scalar is allowed here. */
    public fun decode(text: String, type: FlagValueType): FlagValueBox?
}

// package com.andyyhope.featureflag.json (internal)
internal object JsonReader {
    fun parse(bytes: ByteArray): JsonValue          // unchanged: rejects top-level scalars, as JSONSerialization does
    fun parseFragment(text: String): JsonValue      // A2: same grammar, but any value may be the root
}
```

- **`FlagSchema.write(directory)` (A3).** The signature is unchanged; the behaviour is hardened.
  - **Losing a mkdirs race is not an error.** It throws only if, after `mkdirs()`, the path is still not a directory.
  - **Atomic replacement.** The temporary file is moved over the target with `Files.move(tmp, target, ATOMIC_MOVE, REPLACE_EXISTING)`. On `AtomicMoveNotSupportedException` it falls back to `Files.move(tmp, target, REPLACE_EXISTING)`.
  - **Errors.** A failure throws an `IOException` that names the target path and carries the cause.
  - **Cleanup.** The temporary file never outlives the call.
- **`FlagQRCode` decode (A3).** Before allocating, `decompress` rejects a code whose claimed length is implausible:
  - Rejected when `expected > MAX_DECLARED_LENGTH`, or when `expected > body.size.toLong() * MAX_DEFLATE_RATIO + MAX_DEFLATE_SLACK`. The constants are `MAX_DEFLATE_RATIO = 1032L` (deflate's ceiling) and `MAX_DEFLATE_SLACK = 64L`.
  - A rejected code is `FlagQRCodeException.Corrupt`, as before.
  - A stored (uncompressed) code is unaffected, because its body length equals its claimed length.

### Android sources (A4; package `com.andyyhope.featureflag.android.sources`)

```kotlin
public class SharedPreferencesSource(
    private val preferences: SharedPreferences,
    override val sourceName: String = "SharedPreferences",
) : MutableFlagValueSource, AutoCloseable {
    override fun box(key: FlagKey, type: FlagValueType): FlagValueBox?
    override val changes: Flow<FlagChange>
    override fun setBox(key: FlagKey, box: FlagValueBox?)
    override fun setBoxes(changes: Map<FlagKey, FlagValueBox?>)   // ONE editor, ONE commit()
    /** Announces FlagChange.All, so every flag is read again. For values written by something other than a listener-notified editor. */
    public fun refresh()
    /** Unregisters the preferences listener. */
    override fun close()

    public companion object {
        /** The source a companion edits: the well-known file FlagBridgeContract.PREFERENCES_NAME, MODE_PRIVATE. Put it at the top of the host pole's sources. */
        public fun companion(context: Context, name: String = "Companion"): SharedPreferencesSource
    }
}
```

**Storage, keyed by `FlagKey.rawValue` with no prefix:**

| Flag type | Stored as |
|---|---|
| `Bool` | `putBoolean` |
| `Int` | `putLong` |
| `Float` | `putFloat` |
| `String` | `putString` (raw, not JSON) |
| `Double`, `Data`, `Date`, `Url`, `Array`, `Dictionary` | `putString(FlagValueJson.encode(box))` |

**Reads are type-guided:**
- The stored value's class must match the declared type: `Boolean`, `Long`, `Float` or `String`, and for JSON types a `String` that `FlagValueJson.decode` accepts.
- A mismatch returns `null`. There is no numeric conversion: a stored `Long` read as `Float` returns `null`, and a stored `Boolean` read as `Int` returns `null`.
- `box()` must not copy the whole map (no `getAll()`). Use `contains` with the typed getter, and treat `ClassCastException` as `null`.

**Writes:**
- A write that leaves the stored value unchanged is skipped: no edit and no emission. "Unchanged" means the same stored class and an equal stored value.
- Removing an absent key is a no-op.
- `setBoxes` applies every change in one `edit()` and one `commit()`. `commit()`, not `apply()`, so the provider's `apply` is durable before it answers.

**Changes:**
- Every emission comes from one strongly-held `OnSharedPreferenceChangeListener`, registered in `init`, and goes through a `FlagChangeEmitter`.
  - A non-null key emits `Keys(setOf(FlagKey(key)))`.
  - A `null` key (`clear()` on API 30+) emits `All`.
- The source itself never emits directly from `setBox`. Writes made by another `SharedPreferencesSource` over the same file, such as the provider's, therefore reach this source's collectors too.
- The framework calls listeners inline for a `commit()` made on the main thread, and posts them to the main looper otherwise. Robolectric runs tests on the main thread, so a Robolectric test that commits from another thread must idle the main looper (`shadowOf(Looper.getMainLooper()).idle()`) before expecting an emission.
- **`setBoxes` validates before writing.** It throws `FlagException.UnsupportedValue(key)` when a `Double` or `Float` is non-finite, and writes nothing.

### Bridge contract and schema publishing (A5)

```kotlin
// package com.andyyhope.featureflag.android.bridge
public object FlagBridgeContract {
    public const val PROTOCOL: Int = 1
    public const val PREFERENCES_NAME: String = "com.andyyhope.featureflag.companion"
    public const val SCHEMA_DIRECTORY: String = "featureflag"           // under Context.noBackupFilesDir
    public const val MAX_PAYLOAD_BYTES: Int = 512 * 1024

    public const val METHOD_HELLO: String = "hello"
    public const val METHOD_OVERRIDES: String = "overrides"
    public const val METHOD_APPLY: String = "apply"
    public const val METHOD_SIGNAL: String = "signal"

    public const val KEY_PROTOCOL: String = "protocol"   // Int
    public const val KEY_STATUS: String = "status"       // String, one of STATUS_*
    public const val KEY_MESSAGE: String = "message"     // String?, human-readable detail for a non-OK status
    public const val KEY_PAYLOAD: String = "payload"     // ByteArray, FlagPayload JSON (export format)
    public const val KEY_REMOVE: String = "remove"       // Array<String>, keys whose override is removed
    public const val KEY_HANDLED: String = "handled"     // Boolean
    public const val KEY_SIZE: String = "size"           // Int, bytes, with STATUS_TOO_LARGE

    public const val STATUS_OK: String = "ok"
    public const val STATUS_NOT_PUBLISHED: String = "not-published"
    public const val STATUS_REJECTED: String = "rejected"
    public const val STATUS_TOO_LARGE: String = "too-large"

    public fun authority(hostPackage: String): String = "$hostPackage.featureflag"
    public fun permission(hostPackage: String): String = "$hostPackage.permission.FEATURE_FLAG_BRIDGE"
    public fun schemaUri(hostPackage: String): Uri       // content://<authority>/schema
    public fun overridesUri(hostPackage: String): Uri    // content://<authority>/overrides
    public fun schemaDirectory(context: Context): File = File(context.noBackupFilesDir, SCHEMA_DIRECTORY)
}

// package com.andyyhope.featureflag.android.transport
/** Writes the schema where FlagBridgeProvider serves it. Call on every launch, in Application.onCreate. */
public fun FlagPole<*>.publishSchema(context: Context): File = publishSchema(FlagBridgeContract.schemaDirectory(context))
```

### Signals (A6; package `com.andyyhope.featureflag.android.signals`)

```kotlin
public class FlagSignalChannel internal constructor(private val mainThread: Executor?) {   // null = run inline (tests)
    /** Runs [handler] on the main thread for every delivered signal named in [signals]. Hold the result; close() stops delivery. */
    public fun <S : FlagSignal> observe(signals: List<S>, handler: (S) -> Unit): AutoCloseable
    /**
     * Delivers the signal named [name] to every observer whose list contains it, waiting up to [timeout] for the handlers.
     * Returns true when at least one handler ran to completion. Called by FlagBridgeProvider; safe from any thread.
     * When called on the main thread it runs the handlers inline (no deadlock).
     */
    public fun deliver(name: String, timeout: Duration = DELIVERY_TIMEOUT): Boolean

    public companion object {
        /** The host process's channel. Register observers in Application.onCreate. */
        public val host: FlagSignalChannel          // FlagSignalChannel(Handler(Looper.getMainLooper())::post)
        public val DELIVERY_TIMEOUT: Duration       // 4.seconds (under the client's 5 s default)
    }
}
```

**Delivery rules:**
- One `deliver` runs each matching handler exactly once.
- A name no observer lists returns `false` and runs nothing.
- If two observers list the same name, both run (iOS's per-type delivery).
- A closed observer never runs again.
- `requiresRestart` does not change delivery. The companion UI combines it with `handled` (M3).
- A handler that throws counts as not handled for that observer. The exception is logged with `android.util.Log.w("FeatureFlag", …)` and does not escape `deliver`.

### Provider (B1; `featureflag-bridge`, package `com.andyyhope.featureflag.bridge`)

```kotlin
public class FlagBridgeProvider : ContentProvider()   // everything else private/internal
```

**Manifest** (`featureflag-bridge/src/main/AndroidManifest.xml`, merged into the host):

```xml
<permission android:name="${applicationId}.permission.FEATURE_FLAG_BRIDGE" android:protectionLevel="signature" />
<application>
    <provider android:name="com.andyyhope.featureflag.bridge.FlagBridgeProvider"
        android:authorities="${applicationId}.featureflag"
        android:exported="true"
        android:permission="${applicationId}.permission.FEATURE_FLAG_BRIDGE" />
</application>
```

A host that wants `knownSigner` replaces the `<permission>` element in its own manifest with `tools:node="replace"`. That is documented in M4; it is not tested in M2.

**Behaviour:**
- **`onCreate`:**
  - Opens `SharedPreferencesSource.companion(context)`, which is the same `SharedPreferences` instance as the host's.
  - Registers a strongly-held preferences listener. On any change it calls `notifyChange(overridesUri(context.packageName), null)`.
  - Returns `true`.
- **Startup barrier:** before the first `call` or `openFile` is answered, it waits until the main looper has run one posted task, which guarantees `Application.onCreate` has finished. After that it doesn't wait again.
  - On the main thread (Robolectric) it skips the wait.
  - The wait is bounded by 10 s; after that it answers anyway.
- **`call`:** begins with `context.enforceCallingPermission(permission(context.packageName), …)`. This is defence in depth: the manifest permission already blocks opening the provider (S6).
  - Measured on the device: `enforceCallingPermission` refuses every caller in the provider's own process. A host cannot use the bridge on itself; it should use its pole directly. B4 therefore runs the provider in a separate `:host` process.
- **Methods:**
  - `METHOD_HELLO` → `{KEY_PROTOCOL: PROTOCOL}`.
  - `METHOD_OVERRIDES`:
    - Reads the schema with `FlagSchema.read(schemaDirectory(context))`.
    - Collects `source.box(entry.key, entry.valueType)` for each entry. Any key a strict `FlagPayload.decode` of the result would reject is dropped (Review Focus 2). Practically: encode, decode, drop the rejected keys and repeat, at most twice.
    - Answers `{KEY_STATUS: STATUS_OK, KEY_PAYLOAD: bytes}`.
    - When `bytes.size > MAX_PAYLOAD_BYTES`, answers `{STATUS_TOO_LARGE, KEY_SIZE}`.
    - When there is no schema, answers `STATUS_NOT_PUBLISHED`.
  - `METHOD_APPLY` with extras `{KEY_PAYLOAD, KEY_REMOVE}`:
    - `FlagPayload.decode(payload, schema)` validates the payload strictly.
    - A remove key that isn't a schema flag gives `STATUS_REJECTED` with a message listing it.
    - Otherwise it makes one `source.setBoxes(values + removals)` call and answers `STATUS_OK`.
    - A `FlagImportException` or a `FlagException.UnsupportedValue` (a non-finite number, which `FlagPayload.decode` accepts from `-1e400`) gives `STATUS_REJECTED` with `KEY_MESSAGE = e.message`. Nothing escapes the provider.
    - There is no schema: `STATUS_NOT_PUBLISHED`.
  - `METHOD_SIGNAL` with `arg = name` → `{KEY_HANDLED: FlagSignalChannel.host.deliver(name)}`.
  - Unknown method → `IllegalArgumentException("Unknown bridge method '<method>'.")`.
- **`openFile(schemaUri, "r")`:** a read-only `ParcelFileDescriptor` of the published schema file. A missing file throws `FileNotFoundException`. Any other path throws `FileNotFoundException`.
- **`query`/`insert`/`update`/`delete`/`getType`:** `null`/`0`. The bridge has no table API.

### Client (B2, B3; package `com.andyyhope.featureflag.android.bridge`)

```kotlin
public class FlagBridgeClient(
    context: Context,
    public val hostPackage: String,
    public val timeout: Duration = 5.seconds,
) {
    /** Checks everything a companion needs, in the order it is worth fixing, and loads the host's schema. Never throws. */
    public suspend fun connect(): FlagBridgeConnection
    /** True when the host ran a handler for [signal]; false on no observer, timeout, or an unreachable host. Never throws. */
    public suspend fun send(signal: FlagSignal, timeout: Duration = this.timeout): Boolean
    /** A live view of the host's companion overrides, validated against [schema]. Close it when done. */
    public fun source(schema: FlagSchema, name: String = "Companion"): FlagBridgeSource
}

public sealed interface FlagBridgeConnection {
    public val message: String?                       // null only for Connected
    public data class Connected(public val schema: FlagSchema) : FlagBridgeConnection
    public data class UsesPermissionMissing(public val permission: String) : FlagBridgeConnection
    public data class HostNotFound(public val hostPackage: String) : FlagBridgeConnection
    public data class PermissionDenied(
        public val hostPackage: String,
        public val hostCertificates: List<String>,       // SHA-256, uppercase hex, no separators
        public val companionCertificates: List<String>,
    ) : FlagBridgeConnection
    public data class BridgeNotInstalled(public val hostPackage: String) : FlagBridgeConnection
    public data class Unresponsive(public val hostPackage: String, public val timeout: Duration) : FlagBridgeConnection
    public data class Incompatible(public val reason: String) : FlagBridgeConnection
    public data object NotPublished : FlagBridgeConnection
}
```

**`connect()` order:**
1. **The companion's own `requestedPermissions`** must contain `permission(hostPackage)`. If not → `UsesPermissionMissing`.
2. **`getPackageInfo(hostPackage)`:** `NameNotFoundException` → `HostNotFound`.
3. **`checkSelfPermission(permission)`:** denied → `PermissionDenied`, with both certificate lists from `GET_SIGNING_CERTIFICATES` (`GET_SIGNATURES` below API 28).
4. **`acquireUnstableContentProviderClient(authority)`:**
   - `null` → `BridgeNotInstalled`.
   - `SecurityException` → `PermissionDenied`.
5. **`hello`** on `Dispatchers.IO` within `withTimeoutOrNull(timeout)`:
   - timeout → `Unresponsive`;
   - protocol ≠ `PROTOCOL` → `Incompatible`.
6. **Schema:** `openFile(schemaUri, "r")` and `FlagSchema.parse(bytes)`:
   - `FileNotFoundException` → `NotPublished`;
   - `FlagSchemaException` → `Incompatible(e.message)`.
7. Otherwise → `Connected(schema)`.

**Rules for every call** (`connect`, `send`, the source):
- The client acquires an unstable client per operation and closes it afterwards.
- A `DeadObjectException` is retried once with a fresh client.

**Messages (verbatim; `message` returns these):**

| Status | Message |
|---|---|
| `UsesPermissionMissing` | `This app does not request '<permission>'. Add <uses-permission android:name="<permission>" /> to the companion's manifest.` |
| `HostNotFound` | `No app with the package '<hostPackage>' is installed. Install and run the host app, and check the package name: a debug build often adds a suffix such as '.debug'.` |
| `PermissionDenied` | `'<hostPackage>' only lets apps signed with its own key connect. Sign this app with the same key, or list this app's certificate in the host's knownSigner permission (Android 12 and later). Host: <comma-separated hostCertificates>. This app: <comma-separated companionCertificates>.` |
| `BridgeNotInstalled` | `'<hostPackage>' does not include featureflag-bridge. Add it to the host app's dependencies.` |
| `Unresponsive` | `'<hostPackage>' did not answer within <timeout>. It may be stuck starting up; open it once, then try again.` |
| `Incompatible` | `reason`, which is the `FlagSchemaException` message, or `The host speaks bridge protocol <n>; this companion speaks <PROTOCOL>. Update whichever app is older.`, or `'<hostPackage>' failed while answering the bridge: <message, or the exception's simple class name>. Update whichever app is older, then try again.` |
| `NotPublished` | `FlagSchemaException.NotPublished().message` (core's text) |

`<timeout>` uses `Duration.toString()`, for example `5s`.

```kotlin
public sealed class FlagBridgeException(message: String, cause: Throwable? = null) : RuntimeException(message, cause) {
    public class NotPublished : FlagBridgeException("No schema has been published. The host app writes one with publishSchema(), so run it at least once.")
    public class Rejected(public val reason: String) : FlagBridgeException("The host rejected the change: $reason")
    public class TooLarge(public val bytes: Int, public val limit: Int) :
        FlagBridgeException("The change is $bytes bytes; the bridge carries at most $limit. Send fewer overrides at once.")
    public class Unavailable(cause: Throwable?) :
        FlagBridgeException("The host could not be reached. Open the host app once, then try again.", cause)
}

public class FlagBridgeSource internal constructor(/* client, schema, name */) : MutableFlagValueSource, AutoCloseable {
    override val sourceName: String                    // `name`, default "Companion"
    override fun box(key: FlagKey, type: FlagValueType): FlagValueBox?   // from an in-memory cache; never IPC
    override val changes: Flow<FlagChange>              // FlagChangeEmitter
    /** Blocking IPC: one METHOD_APPLY. Call off the main thread. Throws FlagBridgeException. */
    override fun setBox(key: FlagKey, box: FlagValueBox?)
    /** Blocking IPC: one METHOD_APPLY carrying every change, one host commit. Throws FlagBridgeException. */
    override fun setBoxes(changes: Map<FlagKey, FlagValueBox?>)
    /** Blocking IPC: re-reads the host's overrides; emits All when anything differs. Throws FlagBridgeException. */
    public fun refresh()
    /** Unregisters the ContentObserver and stops its thread. */
    override fun close()
}
```

**`FlagBridgeSource` behaviour:**
- **Construction:** `client.source(schema)` registers a `ContentObserver` on `overridesUri`, served by a private `HandlerThread`, then runs one `refresh()`. A failure in that first refresh leaves an empty cache and is not thrown.
- **Observer:** each `onChange` runs `refresh()` on the observer thread; a failure there is swallowed.
- **Writes:** `setBox` is `setBoxes(mapOf(key to box))`. `setBoxes`:
  1. builds `FlagPayload(values = non-null entries).jsonBytes()` and the remove list;
  2. throws `TooLarge` when the payload exceeds `MAX_PAYLOAD_BYTES`;
  3. calls `METHOD_APPLY`;
  4. maps the status: `STATUS_REJECTED` → `Rejected(message)`, `STATUS_NOT_PUBLISHED` → `NotPublished`, unreachable → `Unavailable`;
  5. on `STATUS_OK`, updates the cache and emits `Keys(changed keys)`.
- **Reads:** `refresh()` handles `METHOD_OVERRIDES`:
  - `STATUS_OK` → `FlagPayload.decode(payload, schema)`, replace the cache, and emit `All` if it changed;
  - `STATUS_TOO_LARGE` → `TooLarge(size, MAX_PAYLOAD_BYTES)`;
  - `STATUS_NOT_PUBLISHED` → `NotPublished`.

## Gaps the sub-plans filled while verifying

Both sub-plans were executed in throwaway worktrees before being committed. Where the contract above was silent or wrong, they chose as follows. Each sub-plan's "Contract issues found" section has the detail.

| Area | Choice | Plan |
|---|---|---|
| `FlagBridgeContract` | A4 creates it with only `PREFERENCES_NAME`; A5 replaces the file with the full object. | M2a |

| `FlagSchema.write` | `mkdirs()` gives no cause, so the `IOException` names the path without one. | M2a |
| `FlagSignalChannel.host` | Posts through a lambda over a main-looper `Handler`, which behaves the same as `Handler(…)::post`. | M2a |
| Unit-test task | AGP 9 makes `testDebugUnitTest` only; there is no `testReleaseUnitTest`. | M2a |
| `connect()` timeout | One `timeout` covers acquire, `hello` and the schema read together. A blocking binder call cannot be interrupted, so it runs in a detached `async` that `withTimeoutOrNull` abandons. | M2b |
| Dead host | A host that dies again on the retry is `Unresponsive`. A `SecurityException` from `call()` is `PermissionDenied`. | M2b |
| Provider schema | An unreadable schema file is treated as not published. | M2b |
| `overrides` | Non-finite values are dropped before encoding. | M2b |
| Unknown remove key | The plan defines the `STATUS_REJECTED` message that lists the key. | M2b |
| `FlagBridgeSource` | `client.source()` blocks for its first refresh, which is one IPC. An unknown status or a missing provider is `Unavailable`. A decode failure after the host changed its schema is `Rejected`, with wording M3 may want to revisit. | M2b |

## Reconciliation notes

- **`FlagException.NoMutableSource`** already names `SharedPreferencesSource` (M1). Nothing changes.
- **`FlagChangeEmitter.subscriberCount` is internal to core.** Android tests that need "unsubscribed" behaviour observe it through emissions, not the counter.
- **Core test helpers aren't visible to the Android modules.** `Fixtures`, `goldenSchema` and `GoldenFlagsSpec` live in core's test source set. Android tests build their own small schemas by hand, and need no golden files. A1's `featureflag.fixtures` plugin still applies to Android unit-test tasks, so a later task can read `fixtures/` the same way.
- **detekt** must run on `src/main/kotlin`, `src/test/kotlin` and `src/androidTest/kotlin` of the Android modules. With AGP's built-in Kotlin, the detekt Gradle plugin may not discover Android source sets on its own, so A1 sets `source` explicitly for Android modules.

  - `ImportRules` duplication, the `apply` → `applyPayload` rename and the other "any time" items stay in the follow-ups note.
  - A3 closes the QR and `FlagSchema.write` items.
