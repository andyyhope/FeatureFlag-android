# M4a Samples Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two sample apps that run the iOS demo's story on Android, from the outside, as a consumer would:
- the build plumbing an app module needs (an application convention, Compose for apps, KSP in an app) and the shared signal enums (A1);
- `:samples:host`: the iOS DemoApp's flags, payloads, mapper and wiring, with the screen's state in a `DemoModel` (A2);
- the host's one Compose screen, a port of iOS `ContentView` (A3);
- `:samples:companion`, the shared and the untrusted debug keys, and `samples/README.md` (A4);
- the end-to-end check on the `Pixel_7` emulator, plus the library's two device suites, recorded in the M4 overview (A5).

**Architecture:**
- **Host.** `DemoApplication.onCreate` builds the `FlagPole` (the companion's `SharedPreferencesSource` first, then the environment configuration's remote and local layers), publishes the schema, registers one `FlagSignalChannel.host.observe` per signal enum and starts `DemoModel`, all before it returns. `DemoModel` is plain Kotlin. It owns the screen's state (`StateFlow<DemoState>`), a snapshot of the flag values and their provenance (`StateFlow<DemoValues>`, re-read on every `pole.changes`), environment switching, payload apply and clear, and signal handling. Its collections start `UNDISPATCHED`, so the first environment's payload is loaded inside `onCreate`.
- **Companion.** One `ComponentActivity` that calls `FlagCompanion(hostPackage = BuildConfig.HOST_PACKAGE, tabs = …)`. The host id lives once, in `gradle.properties`, and reaches the host's `applicationId`, the companion's `<uses-permission>` placeholder and `BuildConfig.HOST_PACKAGE`.
- **Signing.** Both apps' `debug` builds use the committed `samples/keys/shared-debug.keystore`. The companion's `untrusted` build type uses `samples/keys/untrusted.keystore` and installs beside the trusted one.
- **Tests.** The sample's own copies of the scenario tests (JVM), `DemoModel` tests (JVM, `runTest`), Robolectric tests for `onCreate`, the screen, both activities and the companion's manifest, and a JVM test of the two keystores. The device behaviour is A5's runbook.

**Tech Stack:** As the M4 overview: Gradle 9.5.1, AGP 9.1.1 with built-in Kotlin, Kotlin 2.2.10, KSP 2.2.10-2.0.2, Compose BOM `2026.01.00` (Material3 1.4.0, material-icons-core), activity-compose 1.10.1, lifecycle 2.9.1, kotlinx-coroutines 1.10.2, JUnit 4.13.2 + kotlin-test-junit, Robolectric 4.16, AndroidX Test, detekt 1.23.8. On the device side: the `Pixel_7` AVD (API 36), `adb`, `apksigner` from build-tools 36.0.0, and `keytool` from Android Studio's JBR.

## Global Constraints

- **From the M1–M4 overviews, binding here:**
  - **Commits:** imperative sentence case, no type prefix, no trailing period, written as `git commit -m "<subject>" -m "Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>"`. No task pushes.
  - **Every Gradle command runs with** `export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"`, from the repository root. A fresh worktree needs `local.properties` containing `sdk.dir=/Users/andyyhope/Library/Android/sdk` (it is git-ignored).
  - **AGP built-in Kotlin:** never apply `kotlin-android`. Android modules only have debug unit-test tasks (`testDebugUnitTest`).
  - **`allWarningsAsErrors` everywhere.** So: no deprecated API (`PackageManager.getPackageInfo(String, Int)` is deprecated at compileSdk 36; use `PackageInfoFlags`), no unused parameters, and no shadowed implicit `it` (nested lambdas name their parameters).
  - **Robolectric** tests are `@RunWith(AndroidJUnit4::class)` and `@Config(sdk = [36])`. Test names are camelCase sentences, grouped by `// Section` comments. A ported scenario test keeps the core test's name.
  - **No version bumps.** The samples add only what the library modules already use, from the catalog.
  - **Samples are consumer code.** The apps have no `explicitApi()` (the small `:samples:signals` JVM library keeps it). They import only public library API. If a sample needs something internal, stop and report it; never widen visibility.
  - `samples/*` are never published, never ABI-checked and never in Dokka.
  - `gradle.properties` gains `android.disallowKotlinSourceSets=false`, with its reason, and `featureflag.sample.hostId=com.andyyhope.featureflag.sample.host`. Gradle prints `WARNING: The option setting 'android.disallowKotlinSourceSets=false' is experimental.` while configuring; that is expected.
  - **Definition of done:** `./gradlew build detekt` is green and every test the task names passes. A5 also needs the device checklist recorded with screenshots the controller has read, plus `:featureflag-bridge:connectedDebugAndroidTest` and `:featureflag-ui:connectedDebugAndroidTest` green on `Pixel_7`.
- **Found while writing this plan:**
  - **detekt-formatting's `Filename` rule is on.** A file holding a single top-level class is named after that class, so the iOS `RemoteConfigurations.swift` becomes `RemoteConfiguration.kt`.
  - **detekt config.** `config/detekt/detekt.yml` turns `MagicNumber`, `LongMethod` and `MaxLineLength` off. ktlint import ordering (lexicographic, then `java.*`, then `kotlin.*`), `NoUnusedImports`, `NoWildcardImports` and `MultiLineIfElse` (braces on every multi-line `if`) stay on. The code below keeps lines within 120 columns and uses trailing commas.
  - **Material3 opt-ins.** `TopAppBar` needs `@OptIn(ExperimentalMaterial3Api::class)`. `SingleChoiceSegmentedButtonRow` and `SegmentedButton` do not, as in `featureflag-ui`'s `SignalsScreen.kt`.
  - **`CommonExtension` has no type parameters in AGP 9.1.1** (checked with `javap` on `gradle-api-9.1.1.jar`). So `extensions.configure<CommonExtension> { buildFeatures.compose = true }` serves libraries and apps alike.
  - **AGP 9 defaults `buildFeatures.buildConfig` to false.** The companion turns it on for `BuildConfig.HOST_PACKAGE`.
  - **Every region is cited.** Each region a sample marks with `// region snippet:` or `<!-- region snippet: -->` is cited by `samples/README.md` in this plan, so B4's orphan-region rule holds before M4b adds its own citations. Regions never nest.
  - **Split screen on the API 36 image** is `adb shell dumpsys activity service SystemUIService WMShell splitscreen moveToSideStage <taskId> <0|1>`. This was checked on emulator-5554 for this plan: the focused task kept `[0,0][1080,1187]` and the moved task took `[0,1213][1080,2400]`. `uiautomator dump --windows` dumps both halves (also checked). `am start --windowingMode` no longer makes a split on this image.

## Review Focus

The overview's two items this plan owns come first, then three more this plan judges likeliest to bite.

1. **(Overview 1) A companion signed with another key, installed next to the trusted one.** It must install beside it, reach the same host, and show `PermissionDenied` with both certificate digests. It must never show `HostNotFound` or crash.
   - A4 `SampleKeysTest.theUntrustedKeyIsADifferentCertificate`: the two keystores hold different certificates under the contract's aliases and password.
   - A4 Step 8:
     - the merged manifests of **both** `debug` and `untrusted` carry `<uses-permission android:name="com.andyyhope.featureflag.sample.host.permission.FEATURE_FLAG_BRIDGE" />`;
     - `apksigner` shows that the host and the debug companion share a SHA-256 while the untrusted companion's differs;
     - `signingReport` names both stores.
   - A5 Step 13, on the device.
2. **(Overview 2) A signal sent to a host that is not running.** After `adb shell am kill`, a signal must cold-start the host and report handled, with the pole wired before the provider answers.
   - A2 `DemoApplicationTest`, with no looper idling, because everything is done when `onCreate` returns:
     - `onCreatePublishesTheSchemaWhereTheProviderServesIt`;
     - `onCreateRegistersAnObserverForEverySignal`;
     - `onCreateHasLoadedTheEnvironmentsPayloadBeforeItReturns`.
   - A5 Step 10, on the device.
3. **A fetch that fails, or that has nothing.** The app must fall back to the local layer, never keep the previous environment's values, and say why. Pinned by A2 `DemoModelTest.aFailedFetchIsShownAsTheRejection` and `anAbsentRemotePayloadLeavesTheLocalLayerShowing`.
4. **Records with no name, or the same name twice.** The companion can add a blank record, and it must show as "Untitled". A list in which two records share a name is unreadable (`name` is the `@FlagRecordKey`), so the host reads the compiled default list, while provenance still says `Companion` (Contract issue 12). The companion refuses to write such a list, so only a blank name reaches the screen in practice.
   - A3 `DemoScreenTest.aRecordWithNoNameIsShownAsUntitled`.
   - A2 `DemoModelTest.twoRecordsSharingANameReadAsTheCompiledDefault`.
5. **A companion with no host installed.** It must show the "not found" status. It must not show `UsesPermissionMissing` (that would mean the manifest placeholder failed), and it must not crash. Pinned by A4 `CompanionActivityTest.withNoHostInstalledTheCompanionSaysTheHostWasNotFound`.

`build-logic/src/main/kotlin/AndroidApplicationConventionPlugin.kt`

```kotlin
import com.android.build.api.dsl.ApplicationExtension
import io.gitlab.arturbosch.detekt.extensions.DetektExtension
import org.gradle.api.JavaVersion
import org.gradle.api.Plugin
import org.gradle.api.Project
import org.gradle.api.artifacts.VersionCatalogsExtension
import org.gradle.kotlin.dsl.configure
import org.gradle.kotlin.dsl.getByType
import org.jetbrains.kotlin.gradle.dsl.JvmTarget
import org.jetbrains.kotlin.gradle.dsl.KotlinAndroidProjectExtension

/**
 * `featureflag.android-application` — baseline config for the sample apps.
 *
 * The same SDK levels, JDK and warnings-as-errors as `featureflag.android-library`, but an app is
 * consumer code: no `explicitApi()`, and no `featureflag.fixtures`. AGP 9 wires Kotlin itself
 * (built-in Kotlin), so this never applies `kotlin-android`. Unit tests run under Robolectric on a
 * JDK 21 test JVM, with the library convention's test dependencies.
 */
class AndroidApplicationConventionPlugin : Plugin<Project> {
    override fun apply(target: Project) = with(target) {
        pluginManager.apply("com.android.application")
        pluginManager.apply("featureflag.detekt")

        extensions.configure<ApplicationExtension> {
            compileSdk = COMPILE_SDK
            defaultConfig {
                minSdk = MIN_SDK
                targetSdk = TARGET_SDK
            }
            compileOptions {
                sourceCompatibility = JavaVersion.VERSION_17
                targetCompatibility = JavaVersion.VERSION_17
            }
            testOptions {
                unitTests.isIncludeAndroidResources = true
            }
        }

        // Build on JDK 21, emit bytecode for JDK 17, exactly as the library conventions do.
        extensions.configure<KotlinAndroidProjectExtension> {
            jvmToolchain(JDK_TOOLCHAIN)
            compilerOptions {
                jvmTarget.set(JvmTarget.JVM_17)
                allWarningsAsErrors.set(true)
            }
        }

        // With built-in Kotlin detekt cannot discover Android source sets, so name the two an app has.
        extensions.configure<DetektExtension> {
            source.setFrom(files("src/main/kotlin", "src/test/kotlin"))
        }

        val libs = extensions.getByType<VersionCatalogsExtension>().named("libs")
        listOf(
            "kotlin-test-junit",
            "junit",
            "kotlinx-coroutines-test",
            "turbine",
            "robolectric",
            "androidx-test-core",
            "androidx-test-ext-junit",
        ).forEach { alias ->
            dependencies.add("testImplementation", libs.findLibrary(alias).get())
        }
    }

    private companion object {
        const val COMPILE_SDK = 36
        const val MIN_SDK = 26
        const val TARGET_SDK = 36
        const val JDK_TOOLCHAIN = 21
    }
}
```

import com.android.build.api.dsl.CommonExtension
import org.gradle.api.Plugin
import org.gradle.api.Project
import org.gradle.kotlin.dsl.configure

/**
 * `featureflag.compose` — Compose for an Android module, library or app. Apply it after
 * `featureflag.android-library` or `featureflag.android-application`, which register the extension
 * this configures; both extend `CommonExtension`.
 *
 * The compose compiler is a Kotlin compiler plugin released with Kotlin itself, so its version
 * is the catalog's `kotlin`. Compose libraries are added by the module, through the BOM.

class ComposeConventionPlugin : Plugin<Project> {
    override fun apply(target: Project) = with(target) {
        pluginManager.apply("org.jetbrains.kotlin.plugin.compose")

        extensions.configure<CommonExtension> {
            buildFeatures.compose = true
        }
    }
}

package com.andyyhope.featureflag.sample.signals

import com.andyyhope.featureflag.signals.FlagSignal

// Shared by the host, which observes them, and the companion, which sends them. A signal travels
// as its entry name, so both sides must be built from this one file.

// region snippet: sample-app-signal
/** Asks the host to redo or undo its remote configuration. */
public enum class AppSignal(override val signalDescription: String) : FlagSignal {
    RefetchRemoteConfiguration("Re-fetch remote configuration"),
    ClearRemoteConfiguration("Clear remote configuration"),
}
// endregion

/**
 * Asks the host to empty a cache. What PurgeEverything empties is rebuilt at launch, so the host
 * looks unchanged until it restarts, and the companion says "handled — relaunch to see it".
 */
public enum class CacheSignal(
    override val signalDescription: String,
    override val requiresRestart: Boolean = false,
) : FlagSignal {
    PurgeImageCache("Purge the image cache"),
    PurgeEverything("Purge everything", requiresRestart = true),
}
```

**What this task ports, and how it differs from iOS:**
- **Flags, payloads, local layers and the mapper** come from `featureflag-core`'s test-only `scenario/` copies. Apple Pay is renamed throughout, as the contract says:
  - the property is `googlePay` (key `checkout.google-pay`), with remoteKey `featureToggles.checkout.googlePay` and description "Offer Google Pay at checkout";
  - the default record and the staging payload's record are named "Google Pay";
  - the experiments payloads say `checkout.google-pay`.
  - Everything else is verbatim, including the `new-onbaording` typo.
- **`DemoModel` is iOS `DemoModel` without the pole's construction,** which the contract puts in `Application.onCreate`.
  - iOS's `@Published` properties become one `DemoState`.
  - Reads of `flags.*` on redraw become `DemoValues`, re-read on every `pole.changes` emission, so the screen recomposes without touching the pole.
  - iOS's `apply(_:)` is `applyPayload(_)`, so it cannot be confused with Kotlin's `apply`; this matches B1's `FlagPole.applyPayload`.
  - The iOS "App Group unavailable → SnapshotSource('By hand')" fallback has no counterpart, because `SharedPreferencesSource.companion` cannot fail.
- **Robolectric builds a new `DemoApplication` for every test,** while `FlagSignalChannel.host` lives as long as the JVM. So `onTerminate` (which only emulated environments call) closes the observers and cancels the scope.

/**
 * Reads both shapes this backend has ever sent: the dot-path one, by composing DotPathMapper,
 * and a list of `{ "flag", "enabled" }` experiments that no dot path can reach.
 */
object DemoRemoteMapper : RemoteOverrideMapper {
    override fun map(payload: RemoteValue, schema: FlagSchema): Map<FlagKey, RemoteValue> {
        val records = payload.valueAt("experiments") as? RemoteValue.Array ?: return DotPathMapper.map(payload, schema)
        val result = LinkedHashMap<FlagKey, RemoteValue>()
        for (record in records.value) {
            val name = record.valueAt("flag") as? RemoteValue.String
            val enabled = record.valueAt("enabled") as? RemoteValue.Bool
            // Named by the key the schema publishes, so a typo here is reported as an unknown key.
            if (name != null && enabled != null) result[FlagKey(name.value)] = enabled
        }
        return result
    }
}

```kotlin
package com.andyyhope.featureflag.sample.host

import com.andyyhope.featureflag.errors.RemoteOverrideException
import com.andyyhope.featureflag.errors.RemoteOverrideProblem
import com.andyyhope.featureflag.pole.FlagPole
import com.andyyhope.featureflag.remote.EnvironmentConfiguration
import com.andyyhope.featureflag.remote.LayerOutcome
import com.andyyhope.featureflag.sample.signals.AppSignal
import com.andyyhope.featureflag.sample.signals.CacheSignal
import kotlinx.coroutines.CoroutineScope
import kotlinx.coroutines.CoroutineStart
import kotlinx.coroutines.flow.MutableStateFlow
import kotlinx.coroutines.flow.StateFlow
import kotlinx.coroutines.flow.asStateFlow
import kotlinx.coroutines.flow.drop
import kotlinx.coroutines.flow.update
import kotlinx.coroutines.launch

/** What the screen shows besides the flags themselves: iOS DemoModel's published properties. */
data class DemoState(
    /** Which payload is currently applied, if any. */
    val appliedConfiguration: RemoteConfiguration? = null,
    /** Why the last apply was rejected. Payloads are all or nothing, so this is the whole story. */
    val rejection: String? = null,
    /** Proof the flows work: changes counted as they arrive, not read on redraw. */
    val onboardingChanges: Int = 0,
    /** The last signal the companion sent, so the demo can show it arriving. */
    val lastSignal: String? = null,
    val purgedCaches: Int = 0,
    val awaitingRelaunch: Boolean = false,
)

/** Which source supplied one flag's value: a row of "Where each value came from". */
data class Provenance(val key: String, val sourceName: String, val isDefault: Boolean)

/** The flags as the app reads them, taken in one go whenever any source changes. */
data class DemoValues(
    val environment: DemoEnvironment,
    val newOnboarding: Boolean,
    val pageSize: Int,
    val markets: List<String>,
    val googlePay: Boolean,
    val tier: CheckoutTier,
    val endpointHost: String?,
    val oneTap: Boolean,
    val paymentMethods: List<PaymentMethod>,
    val provenance: List<Provenance>,
)

/**
 * Everything the demo screen needs: the pole, the environment configuration that feeds its local
 * and remote layers, and the collections that let the environment flag drive which config is
 * loaded. A port of iOS DemoModel. DemoApplication builds the pole and owns this.
 */
class DemoModel(
    val pole: FlagPole<AppFlags>,
    private val config: EnvironmentConfiguration<DemoEnvironment>,
    private val scope: CoroutineScope,
) {

    private val mutableState = MutableStateFlow(DemoState())
    val state: StateFlow<DemoState> = mutableState.asStateFlow()

    private val mutableValues = MutableStateFlow(read())
    val values: StateFlow<DemoValues> = mutableValues.asStateFlow()

    /**
     * Starts watching the pole. Each collection starts undispatched, so it is subscribed, and the
     * current environment's payload is loaded, before this returns. Application.onCreate calls
     * it, and the bridge provider answers a companion only once onCreate has returned.
     */
    fun start() {
        scope.launch(start = CoroutineStart.UNDISPATCHED) {
            pole.changes.collect { mutableValues.value = read() }
        }
        scope.launch(start = CoroutineStart.UNDISPATCHED) {
            pole.flow(AppFlagsSpec.newOnboarding).drop(1).collect { _ ->
                mutableState.update { state -> state.copy(onboardingChanges = state.onboardingChanges + 1) }
            }
        }
        // region snippet: sample-host-environment
        // The environment flag drives which payload is applied. flow() emits the current value
        // first, so this also performs the initial load, and it never repeats a value.
        scope.launch(start = CoroutineStart.UNDISPATCHED) {
            pole.flow(AppFlagsSpec.environment).collect { environment -> switchTo(environment) }
        }
        // endregion
        mutableValues.value = read()
    }

    /**
     * Loads both layers for an environment: the bundled local config, then the fetched remote one.
     *
     * The environment flag has no remoteKey. If it did, a staging payload could set the
     * environment to production, which would mean the app should have loaded a different config,
     * and loading that could set it back. Leaving the key off is what prevents the loop.
     *
     * The configuration clears each layer before loading it, so a failed fetch falls back to the
     * local config, then the compiled defaults, and never to the previous environment's values.
     */
    suspend fun switchTo(environment: DemoEnvironment) {
        when (val remote = config.load(environment).remote) {
            LayerOutcome.Applied -> mutableState.update { state ->
                state.copy(appliedConfiguration = RemoteConfiguration.forEnvironment(environment), rejection = null)
            }
            LayerOutcome.Absent -> mutableState.update { state ->
                state.copy(appliedConfiguration = null, rejection = null)
            }
            is LayerOutcome.Failed -> mutableState.update { state ->
                state.copy(appliedConfiguration = null, rejection = describe(remote.error))
            }
            // A newer switch is already in flight; let it own the state.
            LayerOutcome.Superseded -> Unit
        }
    }

    /** iOS's environment setter: the choice lands in the Companion source, the highest one. */
    fun selectEnvironment(environment: DemoEnvironment) {
        pole.setOverride(AppFlagsSpec.environment, environment)
    }

    /** Stands in for "your app downloaded a config and handed over the bytes". */
    fun applyPayload(configuration: RemoteConfiguration) {
        try {
            config.remoteSource.apply(configuration.data)
            mutableState.update { state -> state.copy(appliedConfiguration = configuration, rejection = null) }
        } catch (error: RemoteOverrideException) {
            mutableState.update { state -> state.copy(appliedConfiguration = null, rejection = describe(error)) }
        }
    }

    /**
     * Clears just the remote layer, leaving the bundled local config showing through: the local
     * layer earning its place, rather than a fall to the raw defaults.
     */
    fun clearRemote() {
        config.remoteSource.clear()
        mutableState.update { state -> state.copy(appliedConfiguration = null, rejection = null) }
    }

    /** Signals from the companion, on the main thread. */
    fun handle(signal: AppSignal) {
        mutableState.update { state -> state.copy(lastSignal = signal.signalDescription) }
        when (signal) {
            AppSignal.RefetchRemoteConfiguration -> scope.launch { switchTo(pole.flags.environment) }
            AppSignal.ClearRemoteConfiguration -> clearRemote()
        }
    }

    fun handle(signal: CacheSignal) {
        when (signal) {
            // Visible immediately, so this one needs no relaunch.
            CacheSignal.PurgeImageCache -> mutableState.update { state ->
                state.copy(lastSignal = signal.signalDescription, purgedCaches = state.purgedCaches + 1)
            }
            // Emptied now, rebuilt at launch, so nothing here looks different until the app starts
            // again. That is what the signal's requiresRestart says, and why the companion reports
            // "handled — relaunch to see it".
            CacheSignal.PurgeEverything -> mutableState.update { state ->
                state.copy(lastSignal = signal.signalDescription, awaitingRelaunch = true)
            }
        }
    }

    private fun read(): DemoValues {
        val flags = pole.flags
        return DemoValues(
            environment = flags.environment,
            newOnboarding = flags.newOnboarding,
            pageSize = flags.pageSize,
            markets = flags.markets,
            googlePay = flags.checkout.googlePay,
            tier = flags.checkout.tier,
            endpointHost = flags.checkout.endpoint.host,
            oneTap = flags.checkout.express.oneTap,
            paymentMethods = flags.paymentMethods.toList(),
            provenance = pole.schema.flags.map { entry ->
                val resolution = pole.resolution(entry.key, entry.valueType)
                Provenance(entry.key.rawValue, resolution.sourceName ?: "default", resolution.isDefault)
            },
        )
    }
}

/** A rejection is only useful if it names the field and the reason. */
internal fun describe(error: Exception): String {
    if (error !is RemoteOverrideException.Rejected) return error.message ?: error.toString()
    return error.problems.joinToString("\n") { problem ->
        when (problem.kind) {
            RemoteOverrideProblem.Kind.TypeMismatch -> "${problem.remoteKey} — wrong type for ${problem.key.rawValue}"
            RemoteOverrideProblem.Kind.UnknownCase ->
                "${problem.remoteKey} — not a case ${problem.key.rawValue} can represent"
            RemoteOverrideProblem.Kind.UnknownKey -> "${problem.key.rawValue} — no such flag in this app"
        }
    }
}

import android.app.Application
import com.andyyhope.featureflag.android.signals.FlagSignalChannel
import com.andyyhope.featureflag.android.sources.SharedPreferencesSource
import com.andyyhope.featureflag.android.transport.publishSchema
import com.andyyhope.featureflag.pole.FlagPole
import com.andyyhope.featureflag.sample.signals.AppSignal
import com.andyyhope.featureflag.sample.signals.CacheSignal
import kotlinx.coroutines.CoroutineScope
import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.SupervisorJob
import kotlinx.coroutines.cancel

/**
 * The host app. It links featureflag-bridge, never featureflag-ui, so no editor code ships in the
 * app people install.
 *
 * Everything a companion relies on happens in onCreate, before it returns: the bridge provider
 * waits for onCreate before it answers, and a signal can start this process from cold.
 */
class DemoApplication : Application() {

    /** The screen's state. Built in onCreate, so it exists before any activity or provider call. */
    lateinit var model: DemoModel
        private set

    private val scope = CoroutineScope(SupervisorJob() + Dispatchers.Main.immediate)
    private var subscriptions: List<AutoCloseable> = emptyList()

    override fun onCreate() {
        super.onCreate()
        // region snippet: sample-host-wiring
        val config = demoConfiguration()
        // Highest first: a value set by hand in the companion beats the fetched remote config,
        // which beats the bundled local one, which beats the compiled defaults.
        val pole = FlagPole(
            AppFlagsSpec,
            sources = listOf(SharedPreferencesSource.companion(this)) + config.sources,
            applicationName = "Demo",
        )
        // The companion is a separate app and knows nothing of this flag tree until it is
        // published. Do it on every launch, so a newly added flag shows up straight away.
        pole.publishSchema(this)
        model = DemoModel(pole, config, scope)
        // One observer per enum: each `when` stays small and exhaustive, and every observer
        // sees every signal rather than the first one claiming them all.
        subscriptions = listOf(
            FlagSignalChannel.host.observe(AppSignal.entries) { signal -> model.handle(signal) },
            FlagSignalChannel.host.observe(CacheSignal.entries) { signal -> model.handle(signal) },
        )
        model.start()
        // endregion
    }

    /**
     * Only emulated environments call this. Robolectric does, and builds a new application for
     * every test while FlagSignalChannel.host lives as long as the JVM.
     */
    override fun onTerminate() {
        subscriptions.forEach(AutoCloseable::close)
        scope.cancel()
        super.onTerminate()
    }
}

    onApply: (RemoteConfiguration) -> Unit,
    onClear: () -> Unit,
) {
    item { SectionHeader("Rejecting a bad payload") }
    val offered = listOf(
        RemoteConfiguration.experiments,
        RemoteConfiguration.experimentsWithATypo,
        RemoteConfiguration.malformed,
    )
    items(offered) { configuration -> PayloadButton(configuration, onClick = { onApply(configuration) }) }
    if (state.appliedConfiguration != null) {

                modifier = Modifier.padding(horizontal = 4.dp),
                colors = ButtonDefaults.textButtonColors(contentColor = MaterialTheme.colorScheme.error),
            ) { Text(text = "Clear remote payload") }
        }
    }
    val rejection = state.rejection
    if (rejection != null) {
        item { Rejection(rejection) }
    }
    item { SectionFooter(REJECTION_FOOTER) }
}

# Debug-only signing keys

These two keystores sign the sample apps' debug builds. Their passwords are written down in this
repository, so anyone can sign anything with them. **Never use either key for anything real**:
not for a release, not for an app you ship, and not as a certificate a `knownSigner` permission
trusts.

| File | Alias | Store and key password | Certificate | Signs |
|---|---|---|---|---|
| `shared-debug.keystore` | `sample` | `android` | `CN=FeatureFlag Sample (debug only)` | the host's and the companion's `debug` builds |
| `untrusted.keystore` | `untrusted` | `android` | `CN=FeatureFlag Sample untrusted (debug only)` | the companion's `untrusted` build only |

They are committed, rather than generated on each machine, so that "signed with the same key"
holds on every machine and every CI runner: Android's own `~/.android/debug.keystore` differs
from one machine to the next. The untrusted key exists to show what a companion signed with any
other key sees: `PermissionDenied`, with both certificates' SHA-256 digests.

  -storepass android -keypass android -alias untrusted -keyalg RSA -keysize 2048 -validity 10000 \
  -dname "CN=FeatureFlag Sample untrusted (debug only)"
```

A new shared key changes the certificate both apps are signed with, so uninstall both sample

# Samples

Two Android apps: a host app that declares flags, and a companion app that edits them **without
linking a line of the host's code**. They talk through `featureflag-bridge`, a content provider in
the host that only apps signed with the host's key may open.

```sh
./gradlew :samples:host:installDebug :samples:companion:installDebug
```

Run **Demo** first, then **Flags**. Both debug builds are signed with the same committed key,
[`keys/shared-debug.keystore`](keys/README.md), so they work on any emulator or device with no
setup. Never use that key for anything real.

The host shows live values and, underneath, which source supplied each one. The companion
renders the same flags from the published schema — a switch for the `Boolean`, a number field
for the `Int`, a picker for the enum, a URL field — and marks what has been overridden.

Set Google Pay in the companion and the host's "Where each value came from" says `Companion` for
`checkout.google-pay`, while a flag nobody has set says `default`. That line is
`pole.resolution(key, type)`, and it is the answer to "why is this flag false?".

## How the companion knows anything

It has never seen `AppFlags`. On every launch, in `Application.onCreate`, the host builds its pole
and publishes a schema describing its flag tree:

<!-- snippet: sample-host-wiring -->
```kotlin
val config = demoConfiguration()
// Highest first: a value set by hand in the companion beats the fetched remote config,
// which beats the bundled local one, which beats the compiled defaults.
val pole = FlagPole(
    AppFlagsSpec,
    sources = listOf(SharedPreferencesSource.companion(this)) + config.sources,
    applicationName = "Demo",
)
// The companion is a separate app and knows nothing of this flag tree until it is
// published. Do it on every launch, so a newly added flag shows up straight away.
pole.publishSchema(this)
model = DemoModel(pole, config, scope)
// One observer per enum: each `when` stays small and exhaustive, and every observer
// sees every signal rather than the first one claiming them all.
subscriptions = listOf(
    FlagSignalChannel.host.observe(AppSignal.entries) { signal -> model.handle(signal) },
    FlagSignalChannel.host.observe(CacheSignal.entries) { signal -> model.handle(signal) },
)
model.start()
```

which writes `flag-schema.json`:

<!-- snippet-ignore: abridged; the real file lists every flag -->
```json
{ "applicationName" : "Demo",
  "flags" : [ { "key" : "checkout.tier",
                "valueType" : "string",
                "defaultValue" : "free",
                "cases" : ["free", "pro", "enterprise"],
                "description" : "Which pricing tier to present" } ] }
```

The companion asks the host's bridge for that file and builds its editor from it. `cases` is why
the tier flag gets a picker instead of a text field. The companion knows one thing about the
host, its package name, and nothing about its flags.

## The environment flag drives the remote config

`AppFlags` has an `environment` flag — an ordinary enum, not a special type. Changing it applies
that environment's payload:

<!-- snippet: sample-host-environment -->
```kotlin
// The environment flag drives which payload is applied. flow() emits the current value
// first, so this also performs the initial load, and it never repeats a value.
scope.launch(start = CoroutineStart.UNDISPATCHED) {
    pole.flow(AppFlagsSpec.environment).collect { environment -> switchTo(environment) }
}
```

Two details carry the whole pattern.

**The environment flag has no `remoteKey`.**

<!-- snippet: sample-environment-flag -->
```kotlin
/**
 * Deliberately no remoteKey: this flag decides which payload gets fetched, so a payload must
 * not be able to decide it back.
 */
@Flag(description = "Which backend this build talks to")
val environment: DemoEnvironment get() = DemoEnvironment.Production
```

If it did, a staging payload could set the environment to production — which would mean a
different payload should have been fetched, and applying *that* could set it back. Nothing in the
library stops you wiring that loop; leaving the key off is what prevents it. A test asserts the
key stays absent, and another applies a payload that tries to set `environment` and checks it is
ignored.

**The old environment's values are cleared before the new ones are applied.** That leaves a brief
window on compiled defaults, which is deliberate: an app labelled *staging* still running
yesterday's production values looks fine and is wrong, which is worse than one running its own
defaults.

Overrides still outrank everything. Set Google Pay in the companion, then switch environment —
the override survives, and "Where each value came from" says `Companion`. Clear it and the
environment's value shows through.

## Rejecting a bad payload

One button applies a deliberately malformed payload: `onboarding.v2` sends `"yes"` where a boolean
belongs. It is rejected in full, and the valid `googlePay` beside it is not applied either.

`ScenarioTest`, in `host/src/test`, checks every payload against the real flag tree, because a
mistyped dot path fails silently as "the backend sent nothing" — the exact bug the demo exists to
make visible. The tests assert `absentKeys` is empty so a wrong path fails loudly.

## Signals: asking the host to do something

Flags let the companion change what the host *reads*. Signals let it ask the host to *act*. Both
apps depend on `:samples:signals`, so the two sides agree on every name:

<!-- snippet: sample-app-signal -->
```kotlin
/** Asks the host to redo or undo its remote configuration. */
public enum class AppSignal(override val signalDescription: String) : FlagSignal {
    RefetchRemoteConfiguration("Re-fetch remote configuration"),
    ClearRemoteConfiguration("Clear remote configuration"),
}
```

A signal travels as its entry name and carries no payload. The companion calls the host's bridge
provider; the host runs every matching observer on its main thread and answers whether one ran.

### Two groups, not one enum

The demo declares `AppSignal` for configuration and `CacheSignal` for caches, and the companion
files them:

<!-- snippet: sample-companion-tabs -->
```kotlin
FlagCompanion(
    hostPackage = BuildConfig.HOST_PACKAGE,
    tabs = listOf(
        // Overrides first: "what have I changed?" is the question you have before
        // filing a bug or handing the device to someone else.
        FlagCompanionTab.Overrides,
        // Two enums, two groups. The host observes each separately, so its
        // configuration handler never has to mention caches.
        FlagCompanionTab.Signals(
            FlagSignalGroup("Configuration", AppSignal.entries),
            FlagSignalGroup("Caches", CacheSignal.entries),
        ),
        FlagCompanionTab.Flags,
        // The environment flag earns a tab because changing it makes the host load
        // a different payload. Which key that is, is knowledge about this app.
        FlagCompanionTab.Detail(key = "environment", title = "Environment"),
    ),
)
```

The host observes each separately (the two `observe` calls in `onCreate` above), so its
configuration handler never has to mention caches, and each `when` stays exhaustive.

`CacheSignal.PurgeEverything` declares `requiresRestart`, because what it empties is rebuilt at
launch: the host handles it immediately and looks unchanged, so the companion reports "handled —
relaunch to see it" instead of leaving you to conclude nothing happened. Tap it and the host says
so too.

**A signal starts a host that is not running.** Here Android differs from iOS. The bridge is a
content provider, and Android starts a provider's process to answer a call, so a signal sent to a
closed host cold-starts it. `Application.onCreate` builds the pole, publishes the schema and
registers the observers, and only then does the provider answer. That is why all of it happens in
`onCreate`, and none of it later. The companion still waits for the host's answer, so a host with
no observer for that signal reads as "no response" rather than as success.

## Both apps must be signed with the same key

There is no App Group on Android. The host's bridge is guarded by a `signature` permission, which
Android grants only to apps signed with the host's own key. The companion asks for it by name:

<!-- snippet: sample-companion-uses-permission -->
```xml
<uses-permission android:name="${hostId}.permission.FEATURE_FLAG_BRIDGE" />
```

`${hostId}` is a manifest placeholder. The host's id is written once, in the root
`gradle.properties`:

```
featureflag.sample.hostId=com.andyyhope.featureflag.sample.host
```

and becomes the host's `applicationId`, this placeholder, and the companion's
`BuildConfig.HOST_PACKAGE`. The host has no `applicationIdSuffix` in any build type: a suffix
changes the bridge's authority and permission, and the companion would have to name the suffixed
id.

The companion's signing, with the untrusted build next to the trusted one:

<!-- snippet: sample-companion-signing -->
```kotlin
signingConfigs {
    // The key the host is signed with too, so Android grants the host's signature permission.
    getByName("debug") {
        storeFile = file("../keys/shared-debug.keystore")
        storePassword = "android"
        keyAlias = "sample"
        keyPassword = "android"
    }
    // Any other key: the host must refuse this build with PermissionDenied.
    create("untrusted") {
        storeFile = file("../keys/untrusted.keystore")
        storePassword = "android"
        keyAlias = "untrusted"
        keyPassword = "android"
    }
}
buildTypes {
    create("untrusted") {
        initWith(getByName("debug"))
        signingConfig = signingConfigs.getByName("untrusted")
        // Installs beside the trusted companion instead of replacing it.
        applicationIdSuffix = ".untrusted"
        // The library modules have only debug and release.
        matchingFallbacks.add("debug")
    }
}
```

For your own apps, sign the companion with the host's key or, on Android 12 and later, list the
companion's certificate in the host's `knownSigner` permission.

## When a payload has a shape no path can reach

Three of the demo's payloads are ordinary — every flag sits at a dot path, and `remoteKey` finds
it. Two are not:

<!-- snippet-ignore: abridged from RemoteConfiguration.kt -->
```json
{ "experiments": [ { "flag": "new-onboarding", "enabled": true } ] }
```

No path addresses "the record whose flag is new-onboarding", so `DotPathMapper` finds nothing and
the payload applies cleanly while changing absolutely nothing — which is the worst way for this to
fail. `DemoRemoteMapper` reshapes it, and composes the built-in mapper rather than replacing it, so
the older shape still works:

<!-- snippet: sample-remote-mapper -->
```kotlin
/**
 * Reads both shapes this backend has ever sent: the dot-path one, by composing DotPathMapper,
 * and a list of `{ "flag", "enabled" }` experiments that no dot path can reach.
 */
object DemoRemoteMapper : RemoteOverrideMapper {
    override fun map(payload: RemoteValue, schema: FlagSchema): Map<FlagKey, RemoteValue> {
        val records = payload.valueAt("experiments") as? RemoteValue.Array ?: return DotPathMapper.map(payload, schema)
        val result = LinkedHashMap<FlagKey, RemoteValue>()
        for (record in records.value) {
            val name = record.valueAt("flag") as? RemoteValue.String
            val enabled = record.valueAt("enabled") as? RemoteValue.Bool
            // Named by the key the schema publishes, so a typo here is reported as an unknown key.
            if (name != null && enabled != null) result[FlagKey(name.value)] = enabled
        }
        return result
    }
}
```

Tap **List of experiments, misspelled** to see the other half: a mapper is the only thing that can
emit a key no flag has, which is why that is reported as `UnknownKey` rather than skipped. Applying
is all-or-nothing, so the valid record beside it is not applied either.

"""M4a's stand-in for B4's DocsSyncTest: each <!-- snippet: name --> fence in samples/README.md
must equal the dedented region `name` in the samples' sources, and every region must be cited."""
import pathlib
import re
import sys
import textwrap

START = re.compile(r"^\s*(?://|<!--) region snippet: ([a-z0-9-]+)(?: -->)?\s*$")
END = re.compile(r"^\s*(?://|<!--) endregion(?: -->)?\s*$")
CITE = re.compile(r"^<!-- snippet: ([a-z0-9-]+) -->$")

sources = [p for p in pathlib.Path("samples").glob("*/src/**/*") if p.is_file() and p.suffix in {".kt", ".xml"}]
sources += list(pathlib.Path("samples").glob("*/build.gradle.kts"))
regions = {}
for path in sources:
    name, body = None, []
    for line in path.read_text().splitlines():
        if name is None:
            match = START.match(line)
            if match:
                name, body = match.group(1), []
        elif END.match(line):
            regions[name] = textwrap.dedent("\n".join(body)).rstrip("\n")
            name = None
        else:
            body.append(line)

readme = pathlib.Path("samples/README.md").read_text().splitlines()
cited, failures = set(), []
for index, line in enumerate(readme):
    match = CITE.match(line)
    if not match:
        continue
    name = match.group(1)
    cited.add(name)
    fence = []
    for body_line in readme[index + 2:]:
        if body_line.startswith("```"):
            break
        fence.append(body_line)
    if regions.get(name) != "\n".join(fence):
        failures.append(f"{name}: the fence differs from its region, or the region is missing")
failures += [f"{name}: a region nobody cites" for name in sorted(set(regions) - cited)]
print("\n".join(failures) or f"OK: {len(cited)} snippets match their regions")
sys.exit(1 if failures else 0)
```

`build/e2e/ui.py`

```python
"""Reads a `uiautomator dump --windows` file for the M4a device check.

  python3 -I build/e2e/ui.py texts  <dump> [package]          every labelled node: bounds, then label
  python3 -I build/e2e/ui.py centre <dump> <label> [package]  the centre of the first node labelled <label>
  python3 -I build/e2e/ui.py row    <dump> <label> [package]  the other labels on <label>'s line
  python3 -I build/e2e/ui.py field  <dump> [package]          the centre of the first text field

A node's label is its text, else its content description. `centre` also accepts a resource id.
"""
import re
import sys
import xml.etree.ElementTree as ElementTree


def nodes(path, package):
    for node in ElementTree.parse(path).iter("node"):
        if package and node.get("package") != package:
            continue
        label = node.get("text") or node.get("content-desc") or ""
        x1, y1, x2, y2 = map(int, re.findall(r"-?\d+", node.get("bounds", "[0,0][0,0]")))
        yield node, label, (x1, y1, x2, y2)


def main(argv):
    command, path = argv[1], argv[2]
    if command in ("texts", "field"):
        package = argv[3] if len(argv) > 3 else None
        for node, label, (x1, y1, x2, y2) in nodes(path, package):
            if command == "texts" and label:
                print(f"[{x1},{y1}][{x2},{y2}]", label, sep="\t")
            elif command == "field" and node.get("class") == "android.widget.EditText":
                print((x1 + x2) // 2, (y1 + y2) // 2)
                return 0
        return 0 if command == "texts" else 1
    wanted = argv[3]
    package = argv[4] if len(argv) > 4 else None
    found = list(nodes(path, package))
    for node, label, (x1, y1, x2, y2) in found:
        if label != wanted and node.get("resource-id") != wanted:
            continue
        if command == "centre":
            print((x1 + x2) // 2, (y1 + y2) // 2)
        else:
            middle = (y1 + y2) // 2
            print([other for _, other, (_, top, _, bottom) in found if other and other != wanted and top <= middle <= bottom])
        return 0
    print(f"no node labelled {wanted!r}", file=sys.stderr)
    return 1


if __name__ == "__main__":
    sys.exit(main(sys.argv))
```

## Contract issues for the controller

Each item is a place where the contract is silent, slightly wrong, or unworkable as written, with the fix this plan uses. None renames a contract name.

1. **The companion needs more than the contract's three dependencies.** `MaterialTheme` comes from `material3`, which `featureflag-ui` keeps as `implementation`, so the companion adds `platform(compose-bom)` + `material3` (and `ui-test-junit4` for its Robolectric test). All are catalog entries the libraries already use.
2. **The host takes only `lifecycle-runtime-compose`.** The contract says "the lifecycle Compose artifacts". `lifecycle-viewmodel-compose` has no use here, because the model lives in the Application, not in a ViewModel.
3. **The contract's "same strings except Apple Pay → Google Pay" would leave wrong text on Android.** Five iOS strings are adapted (A3):
   - the payload field name in the rejection footer (`applePay` → `googlePay`);
   - `resolution(for:)` → `resolution(key, type)`;
   - the "Combine" section becomes "Flows", with a footer naming `pole.flow(AppFlagsSpec.newOnboarding)`;
   - the signals footer: iOS says a signal to a closed app is lost, and Android starts the app.
4. **Signing lands in A4, not A2.** The keystores are A4's, so the host's `debug` signing config is added to its build file in A4. A2 and A3 use the machine's own debug key.
5. **`matchingFallbacks += "debug"` is written `matchingFallbacks.add("debug")`.** The AGP DSL exposes a setter for `matchingFallbacks`, which makes Kotlin's `+=` ambiguous between `plusAssign` and `plus`-then-assign. `.add` is unambiguous and has the same effect.
6. **The untrusted key's CN is not in the contract.** It is `CN=FeatureFlag Sample untrusted (debug only)`, and `samples/keys/README.md` lists both keys.
7. **iOS `DemoModel.apply(_:)` is `DemoModel.applyPayload(_)`.** That avoids Kotlin's `apply` scope function, the same reasoning as B1's `FlagPole.applyPayload`.
8. **New files outside the contract's file structure:**
   - `samples/screenshots/{host,companion}.png` (A5), for the README's screenshot table as on iOS;
   - `samples/host/…/DemoConfiguration.kt` (A2), which holds `demoConfiguration()` so it is written once;
   - the git-ignored helpers `build/e2e/ui.py` and `build/m4a/check_snippets.py`.
9. **The iOS README's "List of records, misspelled" is stale.** The button is "List of experiments, misspelled" on both platforms, and the Android README uses that.
10. **`DemoApplication.onTerminate` closes the signal observers.** No device calls it. Robolectric does, and builds a new application for every test, while `FlagSignalChannel.host` is a JVM-wide singleton.
11. **"Copy image, then paste" has no paste target in the samples.** A5 pastes into the system clipboard editor, from Android's clipboard overlay, which reads the PNG through `FlagFileProvider` from another app. If THE USER wants a different paste target (for example Messages), A5 Step 11 changes; nothing else does.
12. **A library behaviour for THE USER to decide on (out of M4a's scope).** A companion value of the right type that does not decode wins resolution but is not used:
    - `FlagResolver.resolution` matches only the box's type, so the source holding it is reported;
    - `FlagLookup.read` then falls to the compiled default, not to the next source.

    For example, a record list with a repeated `@FlagRecordKey` reads as the default list, hiding the Remote layer, while provenance says `Companion`. M4a pins the current behaviour in `DemoModelTest.twoRecordsSharingANameReadAsTheCompiledDefault` and documents it in `samples/README.md`. Whether provenance should name a source whose value was not used, or whether reads should fall through to the next source, is a library question, perhaps for B1.
13. **A5 must target `emulator-5554` explicitly.** A second emulator, `emulator-5560` (THE USER's Wear OS image), is attached. Every `adb` call therefore uses `-s emulator-5554`, and every Gradle install or connected-test command runs with `ANDROID_SERIAL=emulator-5554`. A5 never touches `emulator-5560`.
