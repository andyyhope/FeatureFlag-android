# M3 (Compose companion): overview and interface contract

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement the two sub-plans below task-by-task, in order (A1→A6, then B1→B7). Steps use checkbox (`- [ ]`) syntax for tracking.
> This file itself is not a task list. It is the **contract** shared by the two M3 sub-plans. Read it before any task. Every sub-plan task implicitly includes the Global Constraints below, and must use **exactly** the names and signatures in the Interface Contract. A task may add private or internal helpers; it may not rename anything here.

**Goal:** A companion app adds one composable, `FlagCompanion(hostPackage = "com.example.app")`, and gets the iOS companion's screens:
- Overrides, with JSON, QR code and import;
- a flag browser with search, groups and a row editor for every flag type;
- list and record editors;
- a detail tab for one flag;
- signals, with delays, a countdown and recent results.

All of it works against a host app through the M2 bridge.

**Architecture:**
- **Logic first, on the JVM.**
  - M3a builds everything the screens need as plain Kotlin: editor kinds, value text, record lists, the tree, `FlagEditingStore`, the connection session and the signals model.
  - Each is tested with JUnit and no Robolectric, against `SnapshotSource` or small fakes. Only the bridge change (A5) needs Robolectric and the device.
- **Screens second.** M3b draws the screens in Compose Material 3, each tested with Robolectric and `ui-test-junit4`. It finishes with the `FlagCompanion` shell, an on-device smoke test, and then the cuttable countdown notification.
- **One new module.** `featureflag-ui` is an Android library with Compose; companion apps add it. Core gains a public value-text and record-list codec, because the UI cannot reach core's internal JSON.
- **The host does the delay.** A delayed signal is sent at once with a delay; the host waits, then delivers. A companion frozen in the background therefore cannot stall it (S6). Cancelling the send coroutine cancels the host's wait.

**Tech Stack:**
- Inherited from M2: Gradle 9.5.1, AGP 9.1.1 with built-in Kotlin, Kotlin 2.2.10, kotlinx-coroutines 1.10.2, JUnit 4.13.2 + kotlin-test-junit, Turbine 1.2.1, Robolectric 4.16, AndroidX Test, detekt 1.23.8.
- New, matching `../yewki/android`:
  - Compose BOM `2026.01.00` and the compose compiler plugin `org.jetbrains.kotlin.plugin.compose` 2.2.10;
  - `androidx.activity:activity-compose` 1.10.1;
  - `androidx.lifecycle:lifecycle-runtime-compose` and `lifecycle-viewmodel-compose` 2.9.1.
- New, not in yewki: `androidx.core:core` 1.16.0 (for `FileProvider`) and `com.google.zxing:core` 3.5.4.

## Review Focus

These are the inputs and conditions the spec implies but no single task's happy path exercises. Each is pinned by a named test in the task that owns the code.

1. **A stored override the schema no longer accepts.** After a host update, a stored value can have the wrong type or a case that no longer exists. The row must show the default, not "Overridden", and "Reset every override" must still clear it. A record list with a duplicate key is still a string of the right type, so it reads as overridden (as on iOS); the records editor shows its unreadable state with a reset.
   - Pinned by A3 `aStoredValueOfTheWrongTypeReadsAsNotOverridden`, `aStoredValueOutsideAnEnumsCasesReadsAsNotOverridden` and `resettingEverythingClearsUnusableValuesToo`.
2. **The host's schema changes while the companion is open.** The host is reinstalled with a new flag, or its schema stops decoding the stored values.
   - On the next `ON_START`, the session reconnects. When the schema differs, it closes the old source and builds a new store; otherwise it keeps the store, so the screens keep their state.
   - A refresh failure shows as a banner, not a crash. Pinned by A4 `aChangedSchemaReplacesTheStore`, `anUnchangedSchemaKeepsTheStore` and `aFailedRefreshIsShownAndKeepsTheValues`.
3. **A write that the bridge refuses.** Examples are `TooLarge`, a host that died, or `Rejected`. The edit must not look applied, and the user must see why: the row reverts, and the shell's snackbar shows the exception's message.
   - Pinned by A3 `aFailedWriteLeavesTheValueUnchanged` and B6 `aFailedWriteIsShownInTheSnackbar`.
4. **Text the editor cannot read.** Locale commas, whitespace, `inf`/`nan`, fractional-second dates, base64 without padding, and JSON of the wrong shape are all refused. The field reverts and shows the warning; nothing is written.
   - Pinned by A1 `numbersRejectAnythingThatIsNotOne`, `nonFiniteNumbersAreRejected`, `malformedStructuredTextIsRejected` and B1 `anUnreadableEditRevertsAndWarns`.
5. **Leaving the Signals tab, or cancelling, during a countdown.** The host must not deliver a cancelled signal.
   - Leaving cancels the pending send, so the coroutine is cancelled and `METHOD_CANCEL` reaches the host.
   - Pinned by A5 `aCancelledDelayedSignalIsNotDelivered` (device) and A6 `cancellingDuringTheCountdownRecordsNothing`.

## Deviations from the spec

The spec is `docs/superpowers/specs/2026-10-08-android-parity-design.md`. Each line names the change and why.

1. **`FlagEditingStore(schema, source)` has no `reloadSchema`.**
   - A `FlagBridgeSource` is bound to the schema it was built with, so a new schema needs a new source.
   - `FlagCompanionSession` therefore reloads: it reconnects, compares, and builds a new source and store.
   - iOS's `reloadingSchemaWith` closure has no Android counterpart.
2. **Delayed signals are delayed by the host, not the companion (THE USER's choice, 2026-10-14).**
   - The bridge gains `KEY_DELAY`, `KEY_TICKET` and `METHOD_CANCEL`. `PROTOCOL` stays 1, because no host has shipped.
   - A host built before M3 ignores `KEY_DELAY` and delivers at once. That is acceptable, since no M2 host was ever released.
3. **The countdown notification needs no foreground service.**
   - Because the host holds the delay, the companion only shows the countdown: a `Notification.ProgressStyle` with `setRequestPromotedOngoing(true)` on API 36+, and a chronometer that counts down below that.
   - `setTimeoutAfter(delay + timeout)` removes it even if the companion is frozen.
4. **"Copy property list" is dropped.** The spec dropped PLIST.
5. **"Reset every override" asks first.** On iOS it acts at once. Android shows an `AlertDialog` with "Reset every override?", "Every flag goes back to the value the app was built with." and the buttons "Reset" and "Cancel", because the action cannot be undone from the companion.
6. **Write failures are shown, not swallowed.**
   - iOS discards most `setValue`/`reset` errors with `try?`. Across a bridge, failures are real (`TooLarge`, `Unavailable`, `Rejected`), so the shell shows the exception's message in a snackbar.
   - A refused duplicate record key is shown the same way, which also fixes iOS's silent no-op on "Duplicate" in a keyed list.
7. **`nan`, `inf` and `infinity` are refused by the editors.** iOS accepts them and then fails to export. The bridge rejects non-finite numbers anyway (M2 `a409caf`), so accepting them would only produce a failed write.
8. **Import is one commit.**
   - The store applies an import with a single `setBoxes`. `FlagBridgeSource` sends that as one `METHOD_APPLY`, which is one host commit.
   - iOS writes key by key and rolls back in reverse on a failure.
9. **`FlagSignalGroup` takes a list.** iOS takes a type, so Android takes `AppSignal.entries`, as the spec's sample shows. Its `id` is the title, because Kotlin has no type name to hand out.
10. **The end-to-end manual check (host + companion + split screen) moves to M4,** where the sample apps exist.
    - M3's device checks are A5's bridge tests, B6's smoke test (FlagCompanion over an in-process store, with screenshots) and B7's notification screenshots.
    - The spec's "manual check on Pixel_7" for the notification becomes B7's screenshot check.

## Carried from M2

- **`FlagBridgeSource.lastFailure`** (M2 follow-ups) is shown by the shell as a banner over the tab content. The banner holds the exception's message and a "Try again" button that calls `refresh()`. Covered by A4 and B6.
- **`refresh()` on `ON_START`.** The session calls it on its IO dispatcher whenever the shell's lifecycle reaches `ON_START`, after the first. Covered by A4.
- **Writes and `refresh()` block.** Every call is on the store's or session's IO dispatcher. Covered by the Threading constraint.
- **Self-bridging stays refused** (THE USER's choice in M2). `FlagCompanion` is for a separate companion app. The `FlagCompanion` KDoc says so.

### Core additions (A1; `featureflag-core`)

```kotlin
// package com.andyyhope.featureflag.values
/** A box as the text an editor shows and reads back. Not JSON for scalars: a string is unquoted. */
public object FlagValueText {
    /**
     * iOS `displayString`:
     * - bool `true`/`false`; int decimal;
     * - double/float in Swift's `String(Double)` form (core's internal MessageText.double/.float): `3.5`, `1.0`, `1e-05`;
     * - string as is; data as padded standard base64;
     * - date as ISO 8601 UTC to the second (`1970-01-01T00:00:00Z`); url as its text;
     * - array/dictionary as compact JSON with sorted keys and unescaped slashes (FlagValueJson.encode).
     * A collection holding a non-finite number renders as "" instead of throwing.
     */
    public fun format(box: FlagValueBox): String

    /**
     * iOS `FlagValueBox(displayString:as:)`, or null to refuse. No trimming anywhere.
     * - bool: case-insensitive true/yes/1 and false/no/0.
     * - int: optional sign and decimal digits only, within Long.
     * - double/float: `[+-]?(\d+\.?\d*|\.\d+)([eE][+-]?\d+)?`, finite after parsing (`nan`, `inf`, `infinity`, hex floats and Kotlin's `d`/`f` suffixes are refused). A float that overflows to infinity is refused.
     * - string: always accepted.
     * - data: strict padded standard base64 (core's StrictBase64); "" is empty data.
     * - date: `yyyy-MM-ddTHH:mm:ss` with `Z` or `±HH:mm`, no fractional seconds.
     * - url: non-empty and parseable as java.net.URI.
     * - array/dictionary: FlagValueJson.decode(text, type).
     */
    public fun parse(text: String, type: FlagValueType): FlagValueBox?

    /** What a new list element starts as: false, 0, 0.0, "", empty data, [now], https://example.com, [empty element] for an array, {} for a dictionary. */
    public fun empty(type: FlagValueType, now: Instant = Instant.now()): FlagValueBox
}

// package com.andyyhope.featureflag.records
/** A record-list flag's value (a FlagValueBox.String holding a JSON array) as rows, and back. Wraps internal RecordJson. */
public object FlagRecordList {
    /** The rows, or null when the box is not a string, is not a list of records for [shape], or has a duplicate key. */
    public fun decode(box: FlagValueBox, shape: List<FlagRecordField>): List<Map<String, FlagValueBox>>?
    /** Compact sorted-key JSON, as RecordJson.encode. Throws FlagSerializationException.NonFiniteNumber. */
    public fun encode(records: List<Map<String, FlagValueBox>>): FlagValueBox.String
    /** The first key value two rows share, for a box that is otherwise a readable list; null otherwise. */
    public fun duplicateKey(box: FlagValueBox, shape: List<FlagRecordField>): FlagValueBox?
    /** The first key value two of [records] share, at the top level only. */
    public fun duplicateKey(records: List<Map<String, FlagValueBox>>, shape: List<FlagRecordField>): FlagValueBox?
    /**
     * iOS `emptyRecord(alongside:)`: every field at default ?: first case ?: FlagValueText.empty(type).
     * A key value already taken (compared by storage identity, so two dates in one second collide) gets suffixes 2…(taken+2):
     * - string `"N"` or `"<value> N"`; int value+N−1; date +(N−1) s; url `<url>-N`;
     * - the first free suffix wins; with none, or a type that takes no suffix, the colliding value stays.
     */
    public fun emptyRecord(shape: List<FlagRecordField>, alongside: List<Map<String, FlagValueBox>> = emptyList(), now: Instant = Instant.now()): Map<String, FlagValueBox>
}
```

    public data object Integer : FlagEditorKind
    public data object Decimal : FlagEditorKind

    public data object Date : FlagEditorKind
    public data object Url : FlagEditorKind
    public data object Data : FlagEditorKind
    public data class List(val element: FlagValueType) : FlagEditorKind
    public data class Records(val fields: kotlin.collections.List<FlagRecordField>) : FlagEditorKind
    public data object Json : FlagEditorKind

    public val wantsWrappingEditor: Boolean
}

public val FlagSchema.Entry.editorKind: FlagEditorKind

public data class FlagTreeNode(
    val path: List<String>,          // [] at the root
    val title: String?,              // null at the root
    val flags: List<FlagSchema.Entry>,   // direct children: propertyPath.dropLast(1) == path
    val groups: List<FlagTreeNode>,      // schema.groups one level below path, in schema order
) {
    public val id: String                            // path.joinToString(".")
    public val allFlags: List<FlagSchema.Entry>      // flags, then each group's allFlags
    public val isEmpty: Boolean
    public companion object { public fun of(schema: FlagSchema): FlagTreeNode }
}

public data class FlagSection(
    val path: List<String>, val title: String?, val pathDescription: String, val entries: List<FlagSchema.Entry>,
) { public val id: String }

/** A refused record write. Message: "Another record already has that <field>. It is what tells one record from another, so two cannot share it." */
public class FlagRecordEditingException(public val field: String, public val value: FlagValueBox) : RuntimeException(/* the message above */)

/**
 * The companion's model of one host: plain Kotlin over a schema and a source. Reads are synchronous and in-memory. Writes
 * suspend on [writeDispatcher] and throw what the source throws (for a bridge, FlagBridgeException).
 */
public class FlagEditingStore(
    public val schema: FlagSchema,
    private val source: MutableFlagValueSource,
    private val writeDispatcher: CoroutineDispatcher = Dispatchers.IO,
) {
    /** Bumps on every source change and after every write; screens read it to recompose. Starts at 0. */
    public val revision: StateFlow<Long>
    /** Collects source.changes into [revision] until the scope ends. The session calls it once. */
    public fun observeIn(scope: CoroutineScope): Job

    public val tree: FlagTreeNode
    /** Search: trimmed, case-insensitive substring of key or description. An ungrouped section (title null) first, then one per group with direct matches. */
    public fun sections(query: String = ""): List<FlagSection>
    public fun entry(key: FlagKey): FlagSchema.Entry?
    /** The usable override (right type, and in cases when there are cases), else the default. */
    public fun value(entry: FlagSchema.Entry): FlagValueBox
    public fun isOverridden(entry: FlagSchema.Entry): Boolean
    public val overriddenKeys: List<FlagKey>          // schema order
    public fun overriddenCount(node: FlagTreeNode): Int

    public suspend fun setValue(entry: FlagSchema.Entry, box: FlagValueBox)
    public suspend fun reset(entry: FlagSchema.Entry)
    /** One setBoxes clearing every schema key that holds anything, usable or not. Keys outside the schema are left alone. */
    public suspend fun resetAll()

    /** Pretty export JSON of the usable overrides (FlagPayload.jsonBytes). Throws FlagSerializationException.NonFiniteNumber. */
    public fun exportJson(): String
    /** FlagQRCode.encode of the usable overrides. Throws FlagQRCodeException.PayloadTooLarge. */
    public fun qrCode(): String
    /** qrCode(), or null when nothing is overridden or it does not fit. */
    public val copyableQrCode: String?
    /** Trims; "FFQR1:" → FlagQRCode.decode, else FlagPayload.decode; then one setBoxes. Throws FlagImportException, FlagQRCodeException, or what the source throws. */

### Bridge additions (A5)

```kotlin
// FlagBridgeContract (featureflag-android, package com.andyyhope.featureflag.android.bridge)
public const val KEY_DELAY: String = "delay"        // Long ms the host waits before delivering; absent or ≤ 0 = at once
public const val KEY_TICKET: String = "ticket"      // String, unique per delayed send; names it for METHOD_CANCEL
public const val METHOD_CANCEL: String = "cancel"   // arg = ticket; answers STATUS_OK whether or not the ticket was waiting
public val MAX_DELAY: Duration = 60.seconds         // the host clamps KEY_DELAY to 0..MAX_DELAY

// FlagBridgeClient
/**
 * Asks the host to deliver [signal] after [delay] and waits up to delay + [timeout] for the answer.
 * - A delay > 0 carries a fresh ticket; deadline = elapsedRealtime + delay + timeout.
 * - Cancelling the calling coroutine during the wait sends METHOD_CANCEL(ticket) (best effort, NonCancellable, its own short timeout) and rethrows.
 * - A delay of zero sends exactly what M2 sent.
 * Never throws except CancellationException.
 */
public suspend fun send(signal: FlagSignal, timeout: Duration = this.timeout, delay: Duration = Duration.ZERO): Boolean
```

**Provider (`FlagBridgeProvider`):**
- `METHOD_SIGNAL` with `KEY_DELAY > 0`:
  - after the startup barrier, it registers the ticket's latch in a map and waits for `delay` (clamped);
  - a `METHOD_CANCEL` for that ticket ends the wait early, and the call answers `handled = false` without delivering;
  - otherwise it delivers with `deliveryTimeout(extras, enteredAt)`, which is still measured from the deadline, so the delay is not counted twice.
- The ticket is removed from the map in `finally`.
- `METHOD_CANCEL` is answered before the startup barrier. A cancel for a ticket not (yet) waiting answers `STATUS_OK` and is remembered (at most 64 tickets), so a cancel that overtakes its signal still stops it.
- The delay is counted from when the signal arrived, so a cold host's startup counts toward it.
- An expired deadline still answers `false` before the barrier.

## Gaps the sub-plans filled while verifying

The M3a plan was run end to end in a scratch copy before it was written down. These choices were left open by the contract and are now part of it:

- **Session:**
  - A reconnect that is not `Connected` while Ready keeps the store and refreshes it.
  - A changed schema whose source cannot open closes the old source and goes to Unavailable.
  - Only one connection attempt runs at a time.
  - The store writes on the session's `ioDispatcher`.
- **Store:**
  - `tree` is computed once per store.
  - `revision` also bumps after a failed write, so a row reverts.
  - `resetAll()` with nothing stored writes nothing.
  - `observeIn` is subscribed before it returns.
  - `copyableQrCode` is null when an override holds a non-finite number.
- **Import:** `import(text)` chooses its decoder by the `FFQR1:` prefix, so `UnrecognisedFormat` cannot arise from it. `FFQR1:hello` is `Corrupt`, and `hello` is `Malformed`.
- **Value text:**
  - `FlagValueText.parse` reads dates and URLs with core's import readers.
  - It refuses a collection that holds a non-finite number.
- **Tests:** iOS reads records back through a `FlagPole`, but `featureflag-ui` has no KSP. The ports decode with `FlagCodecs.records` over hand-written codecs instead. `testTheThresholdCanBeMoved` is dropped because the threshold is a `const`, and `testTheGroupedTabDescriptor` moves to B6.
- **Accessibility and Android-only words (B1):**
  - `contentDescription`s reuse iOS's own strings: "Reset to the app's default", "Not a valid value for this flag", "Copy value", "Copy JSON" and "Copied".
  - Android adds "Back", "Actions", "Move up", "Move down" and "Delete".
  - The notification channel is "Signal countdowns", and its text is "Sending in".
  - `FlagStrings` is written whole in B1, not grown task by task.
- **Editing (B1, B3):**
  - A text field whose draft equals the value in effect writes nothing. iOS writes on every blur, which marks the flag Overridden.
  - Reordering uses a per-row "Actions" menu (Move up, Move down, Delete), so no drag dependency is needed.
  - Numbers use `KeyboardType.Number` and `KeyboardType.Decimal`; the parse still decides.
- **Shell (B6):**
  - iOS's "Could not do that" alert is not ported. A failed reset-all goes to the snackbar like every other write failure.
  - The `lastFailure` banner sits below the tab content, not over it.
  - A list or record row inside a custom tab pushes onto that tab's own back stack.
  - The Overrides tab's "tune" icon has a single form, so it looks the same selected or not. The unselected Signals icon is `Icons.AutoMirrored.Outlined.Send`.
- **Dropped iOS pieces:** the "App Group is unavailable" line is dropped. iOS's single-type signals form becomes a group with an empty title.
- **QR sheet (B4):** "Save" opens a share chooser for the PNG, and the PNG is written only when it is copied or saved.
- **Notification (B7):**
  - `setRequestPromotedOngoing` and `POST_PROMOTED_NOTIFICATIONS` are API 36.1 and missing from compileSdk 36. B7 sets the extra `"android.requestPromotedOngoing"` and names the permission by its string.
  - One Robolectric test runs on SDK 35 to cover the chronometer path below API 36.
- **Known untested risks in M3b,** which was written without compiling, since A1–A6 did not exist yet:
  - Robolectric's graphics mode for the ZXing bitmap tests;
  - `FileProvider` meta-data under Robolectric;
  - the countdown ring's progress semantics while it animates.

  The task review loop is the net for these.
