# KSP spike (copy at scratchpad/spike-ksp; real repo untouched)

## Answers
1. App module `:samples:host` with ksp:
   (a) WITHOUT `android.disallowKotlinSourceSets=false`: FAILS at configuration:
       "A problem occurred configuring project ':samples:host'.
        > Using kotlin.sourceSets DSL to add Kotlin sources is not allowed with built-in Kotlin.
          Kotlin source set 'debug' contains: [.../samples/host/build/generated/ksp/debug/kotlin, .../ksp/debug/java]
          Solution: Use android.sourceSets DSL instead. ... To suppress this error, set android.disallowKotlinSourceSets=false in gradle.properties."
       (KSP's Gradle plugin adds generated dirs via kotlin.sourceSets; this hits ANY Android module applying the ksp plugin, library included - docs-samples fails identically.)
   (b) WITH it in gradle.properties: `./gradlew :samples:host:assembleDebug` BUILD SUCCESSFUL. Generated into
       samples/host/build/generated/ksp/debug/kotlin/spike/{DemoFlagsSpec,CheckoutFlagsSpec,PaymentMethodFlagRecord,SpendLimitFlagRecord,ExpressFlagsSpec}.kt.
       allWarningsAsErrors did NOT trip on generated code (no w:/e: lines). Both `internal` and public (internal stripped) interfaces/enums/records compile.
       Only error hit was my own: `lateinit var pole: FlagPole<DemoFlags>` public in a public class exposing internal DemoFlags
       ("'public' property exposes its 'internal' type argument 'DemoFlags'") - fixed with `internal lateinit var`. (Public DemoFlags needs none.)
       Gradle prints on configure: "WARNING: The option setting 'android.disallowKotlinSourceSets=false' is experimental. The current default is 'true'." (once per Android project using KSP; harmless)
2. Adding the property changes nothing for existing modules: ran
   `:featureflag-core:test :featureflag-android:assembleDebug :featureflag-android:testDebugUnitTest :featureflag-bridge:assembleDebug :featureflag-bridge:testDebugUnitTest :featureflag-ui:assembleDebug :featureflag-ui:testDebugUnitTest :featureflag-android:lintDebug :featureflag-ui:lintDebug detekt` -> BUILD SUCCESSFUL.
   (Changing the property invalidates the configuration cache once.)
3. `:docs-samples` (featureflag.android-library + ksp, `kspTest(project(":featureflag-ksp"))`): `:docs-samples:testDebugUnitTest` PASSES (Robolectric sdk 36, RobolectricTestRunner, FlagPole(DemoFlagsSpec, listOf(SharedPreferencesSource.companion(context))), asserts flags.pageSize==10; result XML TEST-spike.DemoTest.xml).
   `kspTest` works as a configuration name (AGP+KSP). Tasks: kspDebugKotlin, kspReleaseKotlin, kspDebugUnitTestKotlin, kspDebugAndroidTestKotlin. Test run executed kspDebugUnitTestKotlin. Also needs the property (fails without, see 1a). Note: kspTest alone still registers kotlin.sourceSets for debug (error text names 'debug' source set).
4. `:samples:host:lintDebug` BUILD SUCCESSFUL. `:samples:host:detekt :docs-samples:detekt` BUILD SUCCESSFUL, applying only `id("featureflag.detekt")` (default src/main/kotlin discovery fine for the app; library convention sets explicit source list).

## Minimal working files
gradle.properties: `android.disallowKotlinSourceSets=false`
libs.versions.toml [plugins]: `android-application = { id = "com.android.application", version.ref = "agp" }`
root build.gradle.kts plugins: `alias(libs.plugins.android.application) apply false`
settings.gradle.kts: `include(":samples:host")`, `include(":docs-samples")`  (samples/ dir needs no build file)

samples/host/build.gradle.kts (see file in spike-ksp/samples/host/build.gradle.kts):
```
import com.android.build.api.dsl.ApplicationExtension
import org.jetbrains.kotlin.gradle.dsl.JvmTarget
import org.jetbrains.kotlin.gradle.dsl.KotlinAndroidProjectExtension
plugins { alias(libs.plugins.android.application); alias(libs.plugins.ksp); id("featureflag.detekt") }
extensions.configure<ApplicationExtension> {
    namespace = "spike.host"; compileSdk = 36
    defaultConfig { applicationId = "spike.host"; minSdk = 26; targetSdk = 36; versionCode = 1; versionName = "1" }
    compileOptions { sourceCompatibility = JavaVersion.VERSION_17; targetCompatibility = JavaVersion.VERSION_17 }
}
extensions.configure<KotlinAndroidProjectExtension> {
    jvmToolchain(21)
    compilerOptions { jvmTarget.set(JvmTarget.JVM_17); allWarningsAsErrors.set(true) }
}
dependencies { implementation(project(":featureflag-core")); implementation(project(":featureflag-android")); ksp(project(":featureflag-ksp")) }
```
(`extensions.configure<ApplicationExtension>` works in a plain build script; the `android {}` accessor likely works too given the plugins{} block.)
Manifest: `<application android:name="spike.HostApp" />`. App class: `FlagPole(DemoFlagsSpec, listOf(SharedPreferencesSource.companion(this)))`.

docs-samples/build.gradle.kts:
```
plugins { id("featureflag.android-library"); alias(libs.plugins.ksp) }
android { namespace = "spike.docs" }
dependencies { implementation(project(":featureflag-android")); kspTest(project(":featureflag-ksp")) }
```
(featureflag-android brings featureflag-core via api; convention supplies robolectric/androidx-test/junit/kotlin-test test deps; no explicit featureflag-core dep needed.)

## Gotchas
- The property is required by every Android module using the ksp plugin, repo-wide setting (not per-module).
- library convention enables explicitApi + allWarningsAsErrors: library flags in src/test are fine (test source set, internal decls OK).
- Config-cache entry is rebuilt when the property changes.
- Unrelated: running compound shell commands with cd in this worktree-isolated session was rejected; keep commands simple.
