# ABI check spike (copy at scratchpad/spike-abi; real repo untouched)

## Verdict
BCV 0.18.2 (root) for the 3 JVM modules + android-bcv-bridge 0.2.0 on the 3 Android modules WORKS on AGP 9.1.1 / Gradle 9.5.1 / Kotlin 2.2.10 with configuration cache on. Step 3 (hand-written fallback) not needed.

## Step 1: BCV 0.18.2 at root
- Applied `alias(libs.plugins.bcv)` (NOT apply false) in root `plugins {}`. Config-cache fine.
- `./gradlew apiDump` -> `featureflag-{core,ksp,test}/api/featureflag-<m>.api` (core 1273 lines, ksp 5, test 10). Tasks per JVM module: `apiBuild`, `apiDump`, `apiCheck`.
- Android modules: `tasks --all | grep api` shows nothing for featureflag-android before the bridge was added (silent no-op, as documented). Root `apiDump` does not cover them.

## Step 2: android-bcv-bridge 0.2.0
- Real plugin id `io.github.tjokinen.android-bcv-bridge`; portal has 0.1.0 and 0.2.0 (latest 0.2.0, updated 2026-07-24). Resolved from plugin portal with no extra repos.
- Worked first try with no errors; BCV 0.18.2 on the root classpath supplies the task types (bridge was tested vs 0.18.1; no issue).
- Tasks per Android module: `releaseApiBuild`, `releaseApiDump`, `releaseApiCheck`. Dump at `<module>/api/<module>.api`, build output at `<module>/build/bcv/`.
- `check` depends on them (`check --dry-run` lists `:featureflag-android:releaseApiCheck`, bridge, ui, plus core/ksp/test `apiCheck`). A real `check` run executes all six. So CI needs nothing extra beyond `./gradlew check`. Root `apiDump` does NOT include Android: updating dumps needs `./gradlew apiDump releaseApiDump`.
- Mutation: appended `public fun spikeAddedApi(): Int` to featureflag-android -> `releaseApiCheck` FAILED with a unified diff (`+public final class ...FlagBridgeClientKt { public static final fun spikeAddedApi ()I }`). Same on featureflag-ui. Removing it -> pass.
- Config cache: "Configuration cache entry stored", then "reused" on rerun (releaseApiDump apiDump, and check). Compatible.
- Determinism: ran dump with `--rerun-tasks` after a first dump; `diff` of all six .api files identical.
- Dump sizes: android 218 lines, bridge 15, ui 424.
- No `R` or `BuildConfig` classes in any dump (no buildConfig, no resources classes leaked).

## Gotchas
1. Compose noise: featureflag-ui dump has 15 `ComposableSingletons$*Kt` classes (internal lambdas, public in bytecode). They churn when lambdas change (spurious ABI diffs). Root `apiValidation { ignoredClasses.add("...ComposableSingletons\$BrowserScreenKt") }` DID take effect on the bridge's tasks (class vanished from dump), so list all 15 (or loop over names) in root `apiValidation {}`. Also consider `nonPublicMarkers`. Not done for all 15 in the spike.
2. Compose function names carry hash mangling (`FlagCompanion-45ZY6uE`, value-class params), and Composer/int synthetic params are in signatures; expected.
3. `const val`s in internal-ish objects (`ATTEMPTS`, `HEX_DIGITS`) show as public static fields in android dump: they come from public-in-bytecode class members; review whether source marks them `internal` (BCV can't see Kotlin visibility on const fields in some cases). Not investigated.
4. Failure message says "run :featureflag-android:apiDump" but the real task is `releaseApiDump` (misleading text).
5. Root `apiDump` skips Android; `releaseApiDump` skips JVM. Use both, or `./gradlew apiDump releaseApiDump`. Root `apiValidation` ignores apply to both.
6. Bridge uses BCV-internal types, so pin both versions exactly; add a CI/gradle assertion that `releaseApiCheck` exists in each Android module (silent absence is the BCV failure mode). Single variant only (release); `src/debug` API not checked.
7. In the real repo `check` also runs detekt/lint/tests; spike's `check -x detekt -x test` ran every apiCheck. Note: bash tool in this harness refused commands containing the substring "github" (worktree guard); use script files.
8. Not tested: effect on the real repo's `scripts/`/CI, KSP interplay (none seen), publishing.
