## 3. Consolidated Android-vs-iOS differences (raw material for `DifferencesFromIOS.md`)

Grouped; each line is "difference: reason". Sources: spec (S), M1/M1a-d overview/plans (M1), M2 overview (M2), M2 follow-ups, M3 overview (M3), M1 follow-ups note.

**Declaring and reading**
1. KSP annotations on interfaces instead of Swift macros / property wrappers: Kotlin has no macros; `XSpec`/`XRefs` generated (S).
2. The compiled default is the property's default getter, evaluated **once** against the compiled defaults; non-constant defaults (`Instant.now()`) freeze at first evaluation, and a getter that reads another flag sees that flag's compiled default: so all read paths agree (M1 follow-ups).
3. `description` is an annotation parameter (required); `remoteKey = ""` means none (S, `Annotations.kt`).
4. `$flag` projected values and `@dynamicMemberLookup` replaced by `pole.flags.x.y` plus typed `FlagRef` tree (`AppFlagsSpec.checkout.googlePay`), `pole[ref]`, `pole.flow(ref)`: Kotlin has no projected values (S).
5. Reserved property names `flagDefaults, flagDescriptors, flagContainerDescription, createFlags, flagLookup, flagKeys` (iOS reserves `flags, keys, schema, overrides, descriptors` via dynamic member lookup): generated code members (M1b item 7).
6. Containers must be interfaces, public/internal (not private), no type parameters, no supertypes, flags must be `val` with a getter (K Diagnostics): generation constraints.
7. Nested declarations get `_`-joined generated names (M1b item 8).
8. A group/record in another module is found by naming convention (`XSpec`, `RFlagRecord`); the processor must run in that module too (S, `K Diagnostics.kt:73`).
9. KSP withholds dependents: a container depending on an invalid/cyclic one is not generated; only the root cause is reported (M1 follow-ups).
10. Diagnostics wording ported from Swift; messages are KSP errors not compiler macro errors (S).
11. `FlagRef.defaultValue` is lazy: refs are built while the spec object is initialising (M1b item 9).

**Values**
12. Value-type mapping: Int and Long both wire `int` stored as Long; Instant for Date; URI for URL; ByteArray for Data; `Map<String, T>` only (S).
13. Custom user `FlagValue` conformances are not supported (closed codec set): KSP cannot discover codecs; may open later (S).
14. All enums publish their cases; no `FlagValueCases` opt-in. Enums store by `name` or `FlagStringEnum`/`FlagIntEnum` raw (Int raw is **Long**): S.
15. Records: only primary-constructor properties are fields (no `let` constants in body); nullable = optional; constructor default = field default via a prototype instance; a default reading another parameter sees a placeholder; `@FlagRecordKey`/`@FlagRecordProperty` go on constructor parameters (S).
16. `FlagRecords<R>` is a `List<R>` with no keyed subscript: no `subscript(key)` (code).
17. A record list sent as a JSON string skips enum/nested checks: mirrored iOS quirk, pinned by a test that links an upstream issue (S). Upstream issue filing is outward-facing and still THE USER's call (M1 follow-ups).
18. Remote records reject infinities as `TypeMismatch` (Android fix; no escaping exception) (M1 follow-ups).

**JSON, dates, numbers (byte-compat edges)**
19. Hand-written strict JSON reader/writer, no kotlinx-serialization at runtime: byte-identical output to Apple (S).
20. Reader limits: UTF-16/UTF-32 input rejected; numbers Apple routes through `NSDecimalNumber` (over 17 significant digits / beyond exponent range) differ; integer literal above `Long.MAX_VALUE` reads as a real (found text `1e+19` vs iOS `10000000000000000000`); `\u` escapes accept ASCII hex digits only (M1a probe facts, M1c deviations, M1 follow-ups).
21. `-0.0` reads as `0` (a double flag gets `0.0` where Apple keeps `-0.0`) (M1a).
22. Dates: ISO-8601 UTC to the second; Kotlin accepts only the canonical forms (no single-digit fields, rollover dates, `GMT`, surrounding whitespace, `24:00:00`, `+99:99`); lenient Apple forms are a pinned deviation (M1 overview probe facts).
23. Sorted-key order: non-ASCII keys sort after `z` by code point; may differ from Apple's ICU collation (M1).
24. URLs follow `URL(string:)` percent-encoding; non-ASCII host punycode differs (M1a, `KNOWN_URL_DEVIATIONS`).
25. Message helpers: `quoted` counts code points not grapheme clusters; unusual case lists use the short description (M1c).
26. Error messages ported verbatim except Apple nouns: "UserDefaults" -> "the store"; PLIST/App Group/Core Image messages dropped; `NotPublished` drops the App Group clause; `NoMutableSource` says "Add a SharedPreferencesSource or a SnapshotSource" (M1, M1b item 4, M1c).

**Pole, sources, transport**
27. Combine publishers and `ObservableObject` replaced by cold `Flow`s: `flow(ref)` emits current then distinct changes on the collector's context, no main hop; `changes: Flow<FlagChange>`; Compose via `collectAsStateWithLifecycle` (host artifacts carry no Compose dependency) (S review item 3).
28. Change delivery is lossless (`FlagChangeEmitter` + `ChangeInbox`, merged pending change per subscriber); every custom source must use it; `MutableSharedFlow(DROP_OLDEST)` is wrong (M1 follow-ups).
29. `flow(ref)` adds a final value-level `distinctUntilChanged` (M1c).
30. `UserDefaultsSource` -> `SharedPreferencesSource`: Boolean/Long/Float/String native, other types stored as JSON text; wrong-typed value reads as nothing and falls through; writes that change nothing are skipped; one strongly-held change listener (S, M2).
31. `SharedPreferencesSource.companion(context)` replaces `bridged(ctx)` (M2 deviation 7). Source names "Companion"/"Remote" replace "App Group".
32. App Group, Darwin notifications, foreground re-read replaced by the exported ContentProvider bridge and a `ContentObserver` (S).
33. `FlagPole(applicationName = null)` omits the key; no bundle display name fallback (M1c, M1b item 1).
34. `publishSchema(context)` writes to `noBackupFilesDir/featureflag/flag-schema.json` on every launch from `Application.onCreate`; `publishSchema(directory: File)` for JVM/tests (M2).
35. `apply(payload)` returns Unit (iOS `FlagImportResult`); `importJson`/`importQRCode` return the applied `FlagPayload`; pole `apply` writes key-by-key with best-effort undo (M1c; M2 deviation 5). Possible rename `applyPayload` before API freeze (M1 follow-ups).
36. `removeAllOverrides()` is one `setBoxes` call (M1c).
37. `RemoteOverrideSource.apply(json: ByteArray)` has no `format:`; JSON only (PLIST dropped) (S).
38. `PLIST` export/import/remote dropped (S).
39. Exceptions are classes (own stack trace), nested in sealed hierarchies named `*Exception`; `Kind` entries PascalCase; `UnsupportedFormatVersion(version: Long)`; `Malformed(reason, cause)`; `imageGenerationFailed` dropped (M1c).

**Signals and bridge**
45. `FlagSignal` interface `{ name, signalDescription, requiresRestart }`; an enum's `name` satisfies it; uniqueness is by name (S).
46. Host: `FlagSignalChannel.host.observe(entries) { }` returns `AutoCloseable`, handlers on main thread, register in `Application.onCreate`; companion: `client.send(signal, timeout, delay): Boolean` (S, M3).
47. Sequence numbers and watermarks dropped: `call()` delivers exactly once (S).
48. A signal to a dead host cold-starts it and is handled, even when force-stopped; on iOS it is lost (S6).
49. `send` returns Boolean (handled or not), no distinct `notAcknowledged` error; finer failure detail through `connect()` statuses (code, M2).
50. Delayed signals are delayed by the **host** (`KEY_DELAY`, `METHOD_CANCEL`, `KEY_TICKET`), not the companion; max delay 60 s; protocol stays 1; a pre-M3 host delivers at once (M3 deviation 2).
51. Countdown notification replaces ActivityKit: ProgressStyle Live Update on API 36+, chronometer below, `setTimeoutAfter`; no foreground service; a companion frozen in the background cannot update it (S, M3 deviation 3, M3 execution notes).
52. Bridge permission model: signature-level `<hostAppId>.permission.FEATURE_FLAG_BRIDGE`; optional `knownSigner` (API 31+); companion needs `<uses-permission>` only, no `<queries>` (S6).
53. `FlagBridgeClient.connect()` returns 8 results (Connected, UsesPermissionMissing, HostNotFound, PermissionDenied, BridgeNotInstalled, NotPublished, Unresponsive, Incompatible); iOS shows one failure message naming two causes (M2 deviations 1 and 3).
54. Payload cap 512 KiB both ways (`TooLarge`); provider answers `STATUS_TOO_LARGE` rather than throwing in the host (M2 review focus 1).
55. Startup barrier: provider waits for `Application.onCreate` before answering; client timeout must cover a cold start (S6).
56. Unstable provider client; `DeadObjectException` retried once; companion survives host death (S6).
57. Self-bridging refused: `FlagCompanion` is for a separate app (M2 carry-in, M3).
58. `FlagBridgeClient.source()` is `suspend` (builds on IO); writes and `refresh()` block, call off the main thread; `FlagBridgeSource.lastFailure` publishes the latest refresh failure; refresh replies are applied in ticket order; `send` passes `KEY_DEADLINE` (M2 follow-ups).

66. `nan`, `inf`, `infinity` refused by editors (iOS accepts then fails on export) (M3 deviation 7).

71. English-only strings as Kotlin literals in `FlagStrings`, `contentDescription`s added where iOS has no label (M3).
72. Companion reconnects on `ON_START` after the first; `lastFailure` banner with "Try again" (M3 carried from M2).
73. State in a ViewModel keyed by hostPackage; one back stack per tab via `rememberSaveable`; no navigation-compose dependency (S).

**Platform, build, distribution**

### 5.2 docs-samples module

Constraints found in the repo:
- KSP on a plain JVM module works (`featureflag-core/build.gradle.kts`: `alias(libs.plugins.ksp)` + `kspTest(project(":featureflag-ksp"))`, tests declare `@FlagContainer`). **KSP on an Android module (AGP 9 built-in Kotlin) is unproven** in this repo (spike S3 lists `android.disallowKotlinSourceSets=false`; `gradle.properties` does not set it; no Android module applies KSP). Samples apps (M4a) will have to prove it; docs-samples should not depend on it.
- `featureflag.jvm-library` applies `explicitApi()` and `allWarningsAsErrors` (`JvmLibraryConventionPlugin.kt:20-26`) and adds JUnit/kotlin-test/coroutines-test/Turbine to tests. explicitApi only constrains `main`; test sources are exempt, but warnings-as-errors applies: unused variables or `Deprecation` in a snippet fail the build. detekt (incl. ktlint formatting) runs on tests too, so a snippet must be formatted the way ktlint wants (trailing commas, wrapping at 120).
- The `featureflag.fixtures` plugin hands root dirs to `Test` tasks through system properties and registers them as inputs (`FixturesConventionPlugin.kt`). The same pattern fits `featureflag.docs`.

Recommendation: **two modules, one test**.
1. `:docs-samples` (id `featureflag.jvm-library`, `alias(libs.plugins.ksp)`, `kspTest(project(":featureflag-ksp"))`, deps `testImplementation(project(":featureflag-core"), ":featureflag-test")`). Everything JVM: declarations, pole, sources, remote, audit, transport, `EnvironmentConfiguration`, signals model, `FlagEditingStore` (UI store is plain Kotlin but lives in an AAR; it needs `featureflag-ui`'s Android classes, so those snippets go to module 2). Test-only: all code in `src/test/kotlin` (no published artifact; `publish` skipped).
2. `:docs-samples-android` (id `featureflag.android-library` + `featureflag.compose`, Robolectric 4.16 `@Config(sdk=[36])` like other Android modules). For snippets that need `Context`, `SharedPreferencesSource`, `publishSchema(context)`, `FlagSignalChannel.host`, `FlagBridgeClient`, `FlagCompanion`/`FlagCompanionTab`, `collectAsStateWithLifecycle`. It cannot run KSP, so it consumes declarations from module 1: either (a) module 1 puts the shared declarations in **main** (`public interface AppFlags` with explicit visibility, `ksp(project(":featureflag-ksp"))`) and module 2 `implementation(project(":docs-samples"))`, or (b) module 2's snippets build the pole from a hand-written `FlagContainerSpec` (more code, drifts from generated shape). Prefer (a). If the single-module request is firm, make `:docs-samples` the Android module and prove KSP-on-AGP-9 first (risk R1).
3. `DocsSyncTest` lives in `:docs-samples` and reads both modules' source trees plus all `*.md`. Roots are passed by Gradle as system properties (`featureflag.docs.markdown` = repo `README.md` + `docs/`, `featureflag.docs.sources` = both modules' `src/*/kotlin`, optionally `samples/**/src`), declared as task inputs so editing a doc re-runs the test (copy `FixturesConventionPlugin`'s `inputs.files(...)` pattern).

Because docs Kotlin snippets omit imports and the Kotlin files need them, the region markers go **inside** files, after the imports; the markdown carries no imports (a docs "Imports" convention note in README: snippets omit imports; the full import list is in `docs-samples`).

### 5.3 Marking

Markdown (HTML comment immediately before the fence; invisible on GitHub):

```
<!-- snippet: declaring-nesting -->
```kotlin
@FlagContainer
interface AppFlags { ... }
```
```

Kotlin (IntelliJ-foldable region comments):

```kotlin
// region snippet: declaring-nesting
@FlagContainer
internal interface AppFlags { ... }
// endregion
```

Rules:
- Name = `[a-z0-9-]+`, unique per source tree; one region may be cited by several docs (the same declaration reused in README and Getting Started).
- Extraction: lines strictly between the markers, `trimIndent()` style common-indent removal (regions inside a `@Test fun` body are indented), `\r\n` -> `\n`, trailing blank lines trimmed, no other normalisation. Compare as **exact strings** to the fence body. Tabs are rejected.
- `internal` vs `public`: snippets in docs show what the reader writes. Test-source declarations can be `public`/default, so `interface AppFlags` can be byte-identical without `internal`; in module-1 `main` (needed for option (a)) explicitApi would force `public` on every member: declare the shared containers with `public` in docs too, or keep shared declarations out of the docs text. Decide before writing: **option (a) conflicts with byte-identity of un-annotated declarations.** Mitigation: put shared containers in a separate `shared` source set compiled with explicitApi disabled (`kotlin { explicitApi = ExplicitApiMode.Disabled }` for that module only) or use a thin module with `@file:Suppress`.
- Non-Kotlin fences: `json`/text output blocks use `<!-- output: name -->` and are compared to a **value computed by the test** (e.g. `String(pole.exportJson())` with a pinned `exportedAt`; audit `description(...)`; `RemoteOverrideException.message`), asserting the doc text equals the produced text. This is the strongest check and the one iOS lacks. Hand-written JSON the reader types (payload examples) use `<!-- snippet: ... -->` against a Kotlin raw string constant or a `src/test/resources/docs/*.json` file.
- XML/Gradle fences (manifest `<uses-permission>`, `build.gradle.kts` dependencies): `<!-- snippet: ... -->` compared to files in `docs-samples-android/src/main/` or `samples/*/` (`AndroidManifest.xml` regions via `<!-- region ... -->`, `.kts` via `// region`). At minimum compare against the sample apps' real files, since M4a builds them.
- Deliberately unchecked fences: `<!-- snippet-ignore: reason -->` (e.g. placeholder fragments with `...`). The test lists them and fails if an unmarked ```` ```kotlin ```` fence exists, so nothing is silently unchecked. Shell/`console` fences are exempt by language tag.

### 5.4 DocsSyncTest checks (all must pass)

1. Every ```` ```kotlin ````, ```` ```kts ````, ```` ```xml ````, ```` ```json ```` fence in `README.md` and `docs/**/*.md` has a preceding `snippet`, `output` or `snippet-ignore` marker. (Unmarked fence -> failure listing file:line.)
2. For each `snippet: name`: exactly one `// region snippet: name ... // endregion` in the source trees; text equal after the normalisation above. Failure prints a unified diff and both locations.
3. Every region is cited by at least one doc (no orphans), unless it begins `region snippet-support:` (helper code for a test that is not shown).
4. Each `output: name` fence equals `Outputs[name]()` registered in a Kotlin map in `docs-samples` (computed, deterministic).
5. Region markers are balanced; names valid; duplicates rejected.
6. Relative markdown links (`[x](path.md#anchor)`) resolve to an existing file and heading slug (the analogue of DocC `--warnings-as-errors`); `README.md` doc table links = `docs/` listing.
7. "Run" guarantee is by construction: each region sits in code that a `@Test` executes (regions of declarations are used by tests of the same file). A convention: each doc has `docs-samples/src/test/kotlin/docs/<Doc>Test.kt` with `// MARK`-style sections matching the iOS layout, one `@Test` per snippet group, doc comment naming the snippet. Not mechanically enforced beyond (3).
8. Optional, cheap: forbid `…` and `...` inside `snippet:` fences (placeholders must be `// ...` comments in real compilable code).

Packages: iOS `private Docs*` fixtures collide by name; Kotlin equivalent is one package per document (`docs.gettingstarted`, `docs.declaring`, ...), so generated `AppFlagsSpec` objects do not clash while docs can say `AppFlags` everywhere.

Optional: `./gradlew :docs-samples:test -Pfeatureflag.updateDocs=true` could rewrite fences from regions (mirrors `writeAndroidFixtures`); default off. Not recommended for v1 (more code, hides drift).
