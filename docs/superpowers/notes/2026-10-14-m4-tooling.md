- Central Portal config (https://vanniktech.github.io/gradle-maven-publish-plugin/central/):
  - `mavenPublishing { publishToMavenCentral(); signAllPublications() }`; `publishToMavenCentral(automaticRelease = true, validateDeployment = ...)` optional. Task `publishToMavenCentral` uploads (release stays manual in the portal UI unless automaticRelease / `publishAndReleaseToMavenCentral`).

- **Signing behaviour (source: `MavenPublishBaseExtension.kt`, https://raw.githubusercontent.com/vanniktech/gradle-maven-publish-plugin/main/plugin/src/main/kotlin/com/vanniktech/maven/publish/MavenPublishBaseExtension.kt):** `signAllPublications()` applies the Gradle `signing` plugin and calls `setRequired(version.map { !it.endsWith("-SNAPSHOT") })`. It reads `signingInMemoryKey` only if present. So:
  - With `VERSION_NAME=0.1.0-SNAPSHOT`, signing is not required; `publishToMavenLocal` works with no key.
  - With a release version (`0.1.0`) and no key, `signAllPublications()` makes `publishToMavenLocal` FAIL (no configured signatory). The docs do not describe a skip-if-no-key switch, and the Maven Local/dry-run case is not documented (the "other"/"base" doc pages say nothing).
  - Recommended dry-run: call `signAllPublications()` only when `providers.gradleProperty("signingInMemoryKey").isPresent` (sketch in section 5). Then a release-version dry-run publishes unsigned to `~/.m2`; CI with the key signs. UNVERIFIED by running; verify with `./gradlew publishToMavenLocal -PVERSION_NAME=0.1.0` and `-PVERSION_NAME=0.1.0-SNAPSHOT`.

### 3.2 ABI validation
- **Kotlin/binary-compatibility-validator (BCV)**: latest **0.18.2** (released "02 Sep"; notes: "Prevent configuration crash on hosts unrecognized by Kotlin/Native"). README: plugin in **maintenance mode**; new features go to KGP's experimental validation. Tasks `apiDump`, `apiCheck` (wired into `check`), dumps in `api/`. Supports Gradle 6.1.1+, Kotlin 1.6.20+. https://github.com/Kotlin/binary-compatibility-validator
- **KGP built-in** (https://kotlinlang.org/docs/gradle-binary-compatibility-validation.html): `kotlin { @OptIn(ExperimentalAbiValidation::class) abiValidation { filters { excluded { ... } } } }`, tasks **`checkKotlinAbi` / `updateKotlinAbi`** (`checkKotlinAbi` runs in `check`). The docs do not mention `checkLegacyAbi`/`updateLegacyAbi` (those names came from an earlier KGP dump mode; UNVERIFIED for 2.2.10). Docs say Kotlin/Android projects do not publish JARs, so the `MAVEN_PUBLICATIONS` source does not apply to them. Still experimental (OptIn).
- **The critical finding: neither works on `com.android.library` with AGP 9 built-in Kotlin.**
  - BCV registers tasks by reacting to the Kotlin plugin being applied; built-in Kotlin does not apply it, so `apiDump`/`apiCheck` silently do not exist on Android modules (BCV issue #312). A green `apiCheck` can mean nothing was checked. Sources: https://github.com/amplitude/Amplitude-Kotlin/pull/513 , https://medium.com/@tjokinen/binary-compatibility-validation-silently-stops-working-on-agp-9s-built-in-kotlin-974162978780 (403 on fetch; via search snippet).
  - KGP side: KT-83410 says `KotlinBaseApiPlugin` (used by built-in Kotlin) does not register the ABI validation extension, so the `abiValidation {}` block is an unresolved reference (search snippet: planned 2.5.0-Beta2; UNVERIFIED). The `io.github.tjokinen.android-bcv-bridge` README says Android-library support upstream is "still unsupported", tracked in KT-78025; KMP `com.android.kotlin.multiplatform.library` support arrived in Kotlin 2.4.20 (KT-85950), irrelevant to this repo's plain `com.android.library`.
  - Workarounds in the wild: (a) `io.github.tjokinen.android-bcv-bridge` 0.2.0 (README https://github.com/tjokinen/android-bcv-bridge; plugin portal https://plugins.gradle.org/plugin/io.github.tjokinen.android-bcv-bridge shows 0.1.0 at crawl time): registers `releaseApiDump`/`releaseApiCheck` (wired to `check`), dump at `api/<module>.api`, single variant `release`. Experimental; tested AGP 9.2.0 (names checked on 9.3.0), Gradle 9.6.0, Kotlin 2.3.x, BCV 0.18.1; uses BCV-internal types (`KotlinApiBuildTask`, `KotlinApiCompareTask`) so pin BCV exactly. This repo is AGP 9.1.1 / Gradle 9.5.1 / Kotlin 2.2.10, below the tested matrix: UNVERIFIED. (b) hand-register `apiBuild/apiDump/apiCheck` against `compileReleaseKotlin` (Amplitude, DocxView, awl-debug PRs; code not fetched). (c) `android.builtInKotlin=false` + `android.newDsl=false` (https://developer.android.com/build/migrate-to-built-in-kotlin): works but removed in AGP 10 and this repo's convention plugin already uses `KotlinAndroidProjectExtension` under built-in Kotlin; not recommended.
- Recommendation: BCV 0.18.2 on the three JVM modules (it works there, `kotlin.jvm` is applied) and the bridge plugin on the three Android modules, with a hard CI assertion that the tasks exist. Fallback if the bridge fails on AGP 9.1.1: hand-wire, or ship 0.1.0 with JVM-module ABI gating plus an Android dump script. Do not use KGP `abiValidation` yet (experimental, no Android library support).
- `explicitApi()` is already on, good: BCV only dumps explicit public API. Android dumps omit/include `R` and `BuildConfig` differently per tool (Amplitude PR comment: `BuildConfig` needs `ignoredClasses`); library modules here set no `buildConfig`.

### 5.2 `publish` convention plugin (`build-logic/src/main/kotlin/PublishConventionPlugin.kt`, id `featureflag.publish`)
Register in `build-logic/build.gradle.kts` like the others. Apply it LAST in each publishable module's `plugins {}` (after `featureflag.android-library` / `featureflag.jvm-library`) so Dokka sees the Android plugin first (#4415).
```kotlin
import com.vanniktech.maven.publish.MavenPublishBaseExtension
import org.gradle.api.Plugin
import org.gradle.api.Project
import org.gradle.kotlin.dsl.configure

class PublishConventionPlugin : Plugin<Project> {
    override fun apply(target: Project) = with(target) {
        pluginManager.apply("org.jetbrains.dokka")            // javadoc jar comes from Dokka when applied
        pluginManager.apply("com.vanniktech.maven.publish")   // auto-detects android/kotlin-jvm/java-platform

        extensions.configure<MavenPublishBaseExtension> {
            publishToMavenCentral()
            // Only sign when a key is supplied: a release-version dry-run (publishToMavenLocal) must not need one.
            if (providers.gradleProperty("signingInMemoryKey").isPresent) signAllPublications()
            // GROUP and VERSION_NAME come from gradle.properties; artifactId defaults to the project name (UNVERIFIED default).
            pom {
                name.set(project.name)
                description.set(providers.gradleProperty("POM_DESCRIPTION").orElse("Feature flags for Android"))
                inceptionYear.set("2026")
                url.set("https://github.com/andyyhope/FeatureFlag-android/")
                licenses { license {
                    name.set("The Apache License, Version 2.0")   // CONFIRM actual repo licence
                    url.set("https://www.apache.org/licenses/LICENSE-2.0.txt")
                } }
                developers { developer {
                    id.set("andyyhope"); name.set("Andy Hope"); url.set("https://github.com/andyyhope/")
                } }
                scm {
                    url.set("https://github.com/andyyhope/FeatureFlag-android/")
                    connection.set("scm:git:git://github.com/andyyhope/FeatureFlag-android.git")
                    developerConnection.set("scm:git:ssh://git@github.com/andyyhope/FeatureFlag-android.git")
                }
            }
        }
    }
}
```
Notes: POM property types (`Property<String>`) follow the vanniktech doc's `pom { name = ... }` Kotlin-DSL assignment; with `kotlin-dsl` build-logic use `.set()`. The Dokka plugin in the same convention gets the build-logic classpath entry `dokka-gradle-plugin`. Put POM text in `gradle.properties` (`POM_*`) if preferred. The repo licence file was not checked: CONFIRM before publishing.

### 5.9 `.github/workflows/release.yml`
Dry-run runs on tag push and manual dispatch; the real publish is double-gated: manual dispatch, repository variable `PUBLISH_ENABLED=='true'`, and a protected `maven-central` environment holding secrets. Nothing publishes until THE USER sets these.
```yaml
name: release
on:
  push:
    tags: ['v*']
  workflow_dispatch:
    inputs:
      publish:
        description: 'Publish to Maven Central (needs PUBLISH_ENABLED variable + environment secrets)'
        type: boolean
        default: false
permissions:
  contents: read
jobs:
  dry-run:
    runs-on: ubuntu-latest
    timeout-minutes: 30
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-java@v6
        with: { distribution: temurin, java-version: '21' }
      - uses: gradle/actions/setup-gradle@v6
        with: { cache-read-only: true }
      - name: Version (tag without leading v, else keep gradle.properties)
        id: v
        run: echo "name=${GITHUB_REF_NAME#v}" >> "$GITHUB_OUTPUT"
        if: startsWith(github.ref, 'refs/tags/v')
      - name: Publish to Maven Local (unsigned dry-run)
        run: ./gradlew publishToMavenLocal ${{ steps.v.outputs.name && format('-PVERSION_NAME={0}', steps.v.outputs.name) || '' }}
      - name: List artifacts
        run: find ~/.m2/repository/com/andyyhope/featureflag -type f | sort
      - uses: actions/upload-artifact@v7
        with:
          name: maven-local
          path: ~/.m2/repository/com/andyyhope/featureflag
  publish:
    needs: dry-run
    if: github.event_name == 'workflow_dispatch' && inputs.publish && vars.PUBLISH_ENABLED == 'true'
    runs-on: ubuntu-latest
    timeout-minutes: 45
    environment: maven-central       # THE USER adds required reviewers
    env:
      ORG_GRADLE_PROJECT_mavenCentralUsername: ${{ secrets.MAVEN_CENTRAL_USERNAME }}
      ORG_GRADLE_PROJECT_mavenCentralPassword: ${{ secrets.MAVEN_CENTRAL_PASSWORD }}
      ORG_GRADLE_PROJECT_signingInMemoryKey: ${{ secrets.SIGNING_KEY }}
      ORG_GRADLE_PROJECT_signingInMemoryKeyId: ${{ secrets.SIGNING_KEY_ID }}
      ORG_GRADLE_PROJECT_signingInMemoryKeyPassword: ${{ secrets.SIGNING_KEY_PASSWORD }}
    steps:
      - uses: actions/checkout@v7
      - uses: actions/setup-java@v6
        with: { distribution: temurin, java-version: '21' }
      - uses: gradle/actions/setup-gradle@v6
        with: { cache-read-only: true }
      - name: Upload to Central Portal (stays unreleased until confirmed in the portal)
        run: ./gradlew publishToMavenCentral --no-configuration-cache
```
Notes: `publishToMavenCentral` uploads and validates; release is a click in the portal (use `publishAndReleaseToMavenCentral` only once confident). `--no-configuration-cache` is defensive (signing + config cache historic exception; remove after a successful test). Tag-triggered dry-run only: a tag does NOT publish. User secrets: Central Portal user token, armored GPG private key (+ id, passphrase), namespace `com.andyyhope.featureflag` verified in the portal (DNS TXT).
