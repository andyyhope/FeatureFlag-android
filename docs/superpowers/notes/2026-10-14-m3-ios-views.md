## 1. FlagCompanionView and public API

### FlagCompanionView<Content: View>
- `init(appGroup: String, @ViewBuilder content: @escaping (FlagEditingStore) -> Content)` : full custom body once store is loaded.
- `extension where Content == FlagCompanionTabs`: `init(appGroup: String, tabs: [FlagCompanionTab] = [.overrides, .flags])`.
- Wiring: `@StateObject FlagCompanionLoader(appGroup)`; state enum `.loading` / `.ready(FlagEditingStore)` / `.failed(String)`.
  - `.loading`: centred `ProgressView()`; `.task { loader.load() }` (load runs synchronously on first appear).
  - `load()`: `state = .ready(try FlagEditingStore(appGroup:))`; any throw -> `.failed(message)`.
  - `.ready`: renders `content(store)`; on `UIApplication.didBecomeActiveNotification` (macOS: NSApplication) calls `store.refreshSchema()` (re-reads host schema; replaces only if different, then objectWillChange).
  - `.failed`: `FlagCompanionUnavailableView(message:) { loader.load() }` with Try again; ALSO retries `loader.load()` on every didBecomeActive.
- Failure message (verbatim, `\` = source line continuation): "Run the host app at least once so it can publish its flags, and check that both targets declare the \(appGroup) App Group in their entitlements."
- FlagCompanionUnavailableView (internal): VStack spacing 8, padding; icon `flag.slash` (largeTitle); title (default "No flags yet", headline); message (footnote, secondary, centered); optional button "Try again" (top padding 4).
- Android mapping note: "App Group" == whatever shared store the Android port uses; loader should mirror loading/ready/failed + retry/refreshSchema on foreground (ON_RESUME).

## 2. Screens

Global conventions: every top-level screen (Browser, Overrides, Detail, Signals) owns its own NavigationStack with INLINE title (except QR sheet, which uses default). Lists are `List` (inset grouped on iOS), Forms for Detail/Signals/record editor. Store write errors are swallowed (`try? store.setValue/reset`) except Overrides' reset-all/plist (alert). Store is ObservableObject; cross-process changes (source.changes) refresh on main.

### 2.1 Flags tab: FlagBrowserView
- Nav title: `store.schema.applicationName ?? "Feature Flags"`. Searchable field prompt "Search flags" (binds store.searchText).
- List contents:
  1. If `schema.description` non-nil AND search empty: a Section with Text(description) footnote secondary.
  2. Search empty -> tree: root.flags in a section of FlagRowView (no header); if root.groups non-empty -> Section header = (root.flags.isEmpty ? "" : "Groups") with FlagGroupLink per group.
  3. Search non-empty -> flat `sections`: one Section per FlagSection, header only if title != nil: `section.path.count > 1 ? section.pathDescription : title` (root-ungrouped matches have no header). Rows = FlagRowView.
  4. If `store.sections.isEmpty` (no flags, or no matches): ContentUnavailableMessage. Search empty: title "No flags", message "The app has not published any flags yet." Search non-empty: title "No matches", message "No flag matches \u{201C}<text>\u{201D}."

- Navigation: FlagGroupLink -> FlagGroupView; row of kind records -> FlagRecordsEditorView; row kind list -> FlagArrayEditorView.

## 3. Row editors by kind (FlagRowView; all commit via `try? store.setValue(box, for: entry)`)
Row control sits under the header; toggle/picker/date trailing-aligned (maxWidth infinity), text fields full width.
- toggle: Switch (labels hidden, a11y label = entry.description). Commits immediately on toggle.
- picker(cases): menu-style Picker (dropdown), options = `value.displayString` (raw string, not capitalised). Commits on selection.
- date: compact DatePicker (date + time), labels hidden. Commits on every change.
- integer / decimal: FlagTextField, keyboard numbersAndPunctuation. url: keyboard URL. text/data/json: default keyboard.
- text/integer/decimal/url: single-line rounded-border TextField, monospaced footnote, leading-aligned, no autocorrect, no autocapitalise. `data` and `json`: multi-line wrapping code block: TextEditor min height 54, monospaced footnote, tinted bg (primary 4%), 1pt border primary 12%, corner radius 6, padding L8 R36 V6, copy icon button top-trailing overlay (doc.on.doc -> checkmark green for 1.4 s; a11y "Copy value" / "Copied") copying the current draft.
- FlagTextField commit semantics: local `draft`. Commits when focus is LOST (blur) or on keyboard Submit (single-line). Commit parses via `FlagValueBox(displayString:as:)`; nil -> rejected: draft reverts to store value, trailing orange `exclamationmark.triangle.fill` icon shown inside the field (help "Not a valid value for this flag"; tooltip only on macOS), no store write. A later successful commit clears the warning. While focused, external store changes do NOT overwrite the draft; when unfocused they update it. Multiline editor has no Submit, so only blur commits.
  - Valid-parse rules: see displayString above (bool-like "yes"; int must be Int; data valid base64; json valid JSON of declared type; date/url valid ISO-8601 / URL string).
- list(element): NavigationLink row -> FlagArrayEditorView. LabeledContent: label (footnote secondary) = `"\(n) \(element.typeName)"` + "s" unless n==1 (e.g. "3 strings", "1 int", "2 ints"; "Edit" if value not an array); value = `store.value(for: entry).displayString` (JSON preview, caption monospaced secondary, 1 line, MIDDLE truncation).
- records(fields): NavigationLink row (see 2.5).
- Array element / record field editors: bool Toggle, date DatePicker, enum Picker (record fields only), else FlagTextField single-line; toggle/date/picker commit immediately, text on blur/submit.

### Signal row (Button)
HStack: VStack(2): `signal.description`; if `requiresRestart` caption secondary "Takes effect after a relaunch". Trailing indicator:
- in flight (awaiting ack) -> ProgressView (spinner)
- pending (countdown running) for this signal -> 20x20 ring: faint track accent 20% opacity stroke 3pt, progress arc 3pt round caps starting at top (-90 deg), trim 0 -> progress where progress = clamp((now - start)/duration), i.e. FILLS clockwise as time passes (drawn from the clock each frame via TimelineView). A11y label "Sending in \(Int(duration)) seconds. Tap to cancel."
- idle -> `paperplane` icon, tinted.
Row disabled when: channel nil, OR any send in flight, OR another signal is pending (this one stays enabled so tapping cancels).

### Behaviour (FlagSignalsModel, @MainActor)
- State: delay (default .instant), pending signal, countdown (start, duration), inFlight, history [Attempt] (max 5, newest first), channel = FlagSignalChannel(appGroup) (nil if group unavailable), timeout (default 2 s).
- tapped(signal): if already pending -> cancelPending(); elif delay == instant -> send; else schedule (set pending + countdown, start keep-alive, sleep delay, clear pending, send).
- cancelPending: cancels task, clears pending/countdown, ends keep-alive (no history entry for cancels).
- send: inFlight = signal; `try await signal.send(over: channel, timeout: timeout)`; success -> handled; any thrown error (e.g. FlagSignalError.notAcknowledged) -> not handled; insert Attempt at 0, truncate to 5; inFlight = nil; end keep-alive. Acknowledged send: host must confirm within timeout.
