### 1.4 FlagTreeNode.swift (57 lines)
`struct FlagTreeNode: Identifiable, Hashable, Sendable`:
- `path: [String]` (root is []), `title: String?` (nil at root), `flags: [Entry]` (direct), `groups: [FlagTreeNode]` (direct children), `id = path.joined(".")`.
- `allFlags = flags + groups.flatMap(allFlags)` (this level first, then each child subtree depth-first).

## 2. FlagEditorKind and value text rules

### 2.1 Mapping (`FlagSchema.Entry.editorKind`), evaluated IN THIS ORDER
1. `cases` non-nil AND non-empty -> `.picker(cases)` (wins over everything, e.g. Int-backed enum gets a picker, test `testCasesWinOverTheUnderlyingType`).
2. `recordShape` non-nil AND non-empty -> `.records(recordShape)` (a record flag has `valueType == .string`).
3. Switch on `valueType`:
   - `.bool` -> `.toggle`
   - `.int` -> `.integer`
   - `.double`, `.float` -> `.decimal`
   - `.string` -> `.text`
   - `.date` -> `.date`
   - `.url` -> `.url`
   - `.data` -> `.data`
   - `.array(element)`: element `.array` or `.dictionary` -> `.json`; otherwise `.list(element: element)` (so array of bool/int/double/float/string/data/date/url).
   - `.dictionary` -> `.json`
- Empty `cases` array (`[]`) falls through (test: `.string` + `[]` -> `.text`). Empty `recordShape` falls through.
- There is NO optional/nil concept at the flag level; `FlagValueBox` has no null. Optionals exist only as `FlagRecordField.isOptional` (see 1.9, UI ignores it).

### 2.2 Value types and boxes
`FlagValueType`: bool, int, double, float, string, data, date, url, array(T), dictionary(T). `typeName`: `bool,int,double,float,string,data,date,url,array<T>,dictionary<T>`. `FlagValueBox`: bool(Bool), int(Int 64-bit), double(Double), float(Float 32), string, data(bytes), date, url, array([Box]), dictionary([String: Box]). `matches(type)`: kind-for-kind; arrays/dictionaries check all elements (empty matches any element type).

### 2.3 `displayString` (render)
- bool -> `true`/`false`. int -> decimal `-7`. double -> Swift `String(Double)` (shortest round-trip, e.g. `3.5`, `1.0`, `0.1`, `1e-05`, `1e+16`, `inf`, `nan`); float -> `String(Float)` (e.g. `2.5`, `0.1` stays `0.1`). NOTE: Kotlin `Double.toString` gives `1.0E-5`/`1.0E16`; port should reproduce Swift format or accept the difference (tests only assert `3.5`, `2.5`, `-7`).
- string -> as is. data -> standard base64 WITH padding (`AQI=` for [1,2]), no line breaks. date -> `ISO8601 internet date-time, second precision, UTC, "Z"`: `1970-01-01T00:00:00Z` (fractional seconds dropped). url -> `absoluteString`, no escaping of slashes.
- array/dictionary -> compact JSON of `jsonValue`: sorted keys, `.withoutEscapingSlashes`, no whitespace: `[]`, `{}`, `{"a":1,"b":2}`, `["a","b"]`. JSON element rendering: dates/urls/data become strings; `Float` renders as Double of the float (a float 0.1 prints `0.10000000149011612` inside collections). Serialisation failure -> `""`.
- Non-finite numbers: `displayString` happily renders `inf`/`nan` for scalars; collections containing them: `JSONSerialization` would raise an ObjC exception (uncatchable); `jsonValue` is not guarded here, so the iOS UI can crash if a collection holds NaN. Port should render defensively.

### 2.4 `init?(displayString:as:)` (parse); nil = reject (UI reverts the edit, shows warning icon)
- bool: `string.lowercased()` in {`true`,`yes`,`1`} -> true; {`false`,`no`,`0`} -> false; anything else nil (no trimming; ` true` rejected). The UI normally uses a Switch, but list elements/record fields of bool use switches too, so text bool parse is only reachable via API.
- int: Swift `Int(string)`: base 10 only, optional leading `+` or `-`, no whitespace (` 3` rejected), no decimals (`3.5` rejected), no suffix (`3abc` rejected), empty rejected, overflow beyond Int64 rejected. Equivalent Kotlin: strict `toLongOrNull()` (accepts `+5` and `-5`; also rejects whitespace; verify `"+"`/`"-"` alone are null).
- double: Swift `Double(string)`: C-locale (decimal separator is always `.`; `3,5` rejected; NO locale handling anywhere in the iOS code); accepts `1e5`, `.5`, `5.`, `+1`, `-1`, hex float `0x1p3`, `inf`, `infinity`, `nan` (case-insensitive); rejects empty, whitespace, trailing junk. Kotlin `toDoubleOrNull()` is similar but also accepts a trailing `d`/`f`/`D`/`F` suffix and leading/trailing whitespace is rejected differently: port should pre-validate with a regex and treat `NaN`/`Infinity` the Swift way. Inf/NaN are ACCEPTED by parse and stored, then break JSON export (`FlagSerializationError.nonFiniteNumber`, message in 3.7), so the UI export JSON shows `{}` (the `exportedJSON` fallback) and QR/exports fail.
- float: `Float(string)`: same as double but 32-bit (`Float("1e40")` is `inf` in Swift, so accepted!).
- string: always succeeds, including empty and `{not json}`. Not trimmed.
- data: `Data(base64Encoded: string)` default options: standard alphabet (not base64url), requires correct `=` padding and a length multiple of 4, rejects whitespace/newlines and invalid characters; empty string -> empty Data (valid). `!!!` rejected. Kotlin: `Base64.getDecoder()` (java.util, strict, padding required) is the closest; Android `Base64.DEFAULT` is more lenient (accepts newlines), so use java.util.Base64 or strict check.
- date: `ISO8601DateFormatter` with `.withInternetDateTime` ONLY: requires `yyyy-MM-ddTHH:mm:ssZ` or with offset `+HH:mm`/`Z`; no fractional seconds (rejected), no date-only (`yesterday` rejected). Kotlin: parse with `OffsetDateTime`/`DateTimeFormatter.ISO_OFFSET_DATE_TIME` BUT reject fractional seconds, and then truncate to seconds. The date picker control writes `.date(Date)` directly (any precision), which when stored/exported is second-precision.
- url: `URL(string: string)`: empty -> nil (test). On iOS 16 and earlier invalid URLs (spaces, etc.) return nil; on iOS 17+ Foundation percent-encodes and accepts more. Port rule to match tests: reject empty; recommend `java.net.URI`-style validation requiring a parseable string (decide leniency; only `""` is asserted).
- array/dictionary: `JSONSerialization.jsonObject(with: utf8, options: [.fragmentsAllowed])` -> then `FlagValueBox(jsonValue:as:)` per element type. Rejections: invalid JSON (`[`, `not json`), top level wrong shape (`{}` for array, `[1]` for array<string>), any element of wrong type. JSON rules (`FlagValueBox(jsonValue:as:)`): bool requires a true boolean (1 is NOT bool); int requires non-bool number castable to Int (a JSON `3.0` is accepted as 3 via NSNumber bridging; `3.5` rejected); double/float accept any non-bool number (int ok; float narrows to Float); string requires String; data requires base64 string; date requires ISO8601 string (same as above); url requires String that `URL(string:)` accepts; array/dictionary recurse; dictionary requires string keys. Empty `[]`/`{}` accepted for any element type.
- Date and url do NOT go through JSON parsing: `parseStructured` for `.date`/`.url` passes the raw string straight to `FlagValueBox(jsonValue: string, as: type)`; only array/dictionary use `JSONSerialization` (with `.fragmentsAllowed`, which is irrelevant since the result must be a collection).

### 2.5 Round-trip contracts asserted by tests
- date `1970-01-01T00:00:00Z` <-> 0; data `[1,0xFF]` round trip; url `https://a.example/x`; arrays of arrays `[[1]]` round trip as `array<array<int>>`; `{"a":1}` as `dictionary<int>`; `[]` as `array<int>`; `{}` as `dictionary<bool>`.

## 3. FlagEditingStore

### 3.1 Inputs
- `schema: FlagSchema` (flat: `flags[Entry]`, `groups[Group]`, `description`, `applicationName`, `generatedAt`, `formatVersion`). `Entry`: key, propertyPath, description, valueType, defaultValue, cases?, remoteKey?, recordShape?. `Group`: propertyPath, description. `FlagSchema` is Equatable over ALL fields including `generatedAt`.
- `source: MutableFlagValueSource`: `box(for key, as type) -> FlagValueBox?`, `setBox(box?, for key) throws` (nil removes), `changes: Publisher<FlagChange>` (`.all` or `.keys(Set)`).
- `reloadSchema: () -> FlagSchema?` (default returns nil). The App Group init passes `{ try? FlagSchema(appGroup:) }`.
- State held: `schema` (replaced by refresh), `searchText`, subscription to `source.changes`.

### 3.2 Values
- `usableOverride(entry)`: `source.box(key, as: entry.valueType)`; must be non-nil AND `box.matches(entry.valueType)`; AND if `entry.cases` non-empty it must be contained in `cases` (Box equality). Otherwise nil.
- `value(for:) = usableOverride ?? entry.defaultValue`. `isOverridden = usableOverride != nil`. `overriddenKeys` = schema order of overridden entries. `overriddenCount(in: node)` = count of `node.allFlags` overridden.
- Stale/wrong type/enum case no longer valid -> treated as not overridden and the default is displayed (tests).
- An empty array override IS an override (not the same as none).

### 3.3 Mutations
- `setValue(box, for entry)`: `objectWillChange.send()`, `source.setBox(box, key)` (throws propagate). No type validation at this layer: callers (parse functions/controls) guarantee type. Does not check enum membership.
- `reset(entry)`: `setBox(nil, key)`.
- `resetAll()`: for each schema flag where `source.box(for: key, as: type) != nil` (RAW presence, NOT `usableOverride`; so stale wrong-typed values of declared flags are cleared too), `setBox(nil)`. Skips absent keys to avoid cross-process broadcasts per key. Undeclared keys never touched (test: `unrelated.key` survives). On first throw, remaining keys are not cleared (no rollback).
- `setRecords` / `records(for:)`: section 1.9.

### 3.4 Export/import
- `export(as: .json | .plist) throws -> Data`: `FlagPayload(values: overridden values via value(for:))`. JSON: pretty-printed, sorted keys, slashes unescaped: `{"exportedAt": "<ISO8601 Z>", "formatVersion": 1, "values": {...}}`. Plist: XML plist of `propertyListValue` (Android: skip plist or output same JSON; the Overrides tab "Copy property list" is iOS flavoured). Values use JSON rules (section 2.4 reverse): dates ISO8601, data base64, url string, floats as double, records as their JSON text string.
- Exports only usable overrides. Empty -> valid doc with `"values": {}`. Throws `FlagSerializationError.nonFiniteNumber(key)` if any value contains inf/NaN.
- `import(data, as:)`: `FlagPayload.decode(data, as:, valueTypes: schema.valueTypes (first wins on duplicate keys), cases: schema.valueCases (omits empty), recordShapes: schema.recordShapes)` then `apply`.
- `importQRCode(scanned)`: `FlagQRCode.decode(...)` then `apply`. QR format `FFQR1:` + base64url-no-pad of (4-byte big-endian uncompressed length + zlib deflate of the JSON; if deflate cannot shrink, the raw bytes stored verbatim after the length prefix). Max total string length 2953 characters (QR v40-L byte mode). Decode: wrong prefix -> `unrecognisedFormat`; bad base64url or bad/oversize length (>50,000,000), zero length with data, or decompress failure -> `corrupt`. Decoded JSON goes through the normal validation below. Android port: `java.util.zip.Deflater`/`Inflater` (zlib wrapper, so `Deflater()` default with header) to be byte compatible with iOS `COMPRESSION_ZLIB` (note Apple's `COMPRESSION_ZLIB` is RAW DEFLATE without zlib header; the Android core module presumably already has a cross-platform test fixture, check `fixtures/` before implementing).
- Payload decode rules (`FlagPayload.decode`, json): not a JSON object -> `malformed("not a JSON object")`; missing/non-Int `formatVersion` -> `malformed("missing formatVersion")`; version != 1 -> `unsupportedFormatVersion(v)`; missing `values` object -> `malformed("missing values")`. Then per (key, raw) in values: unknown key -> problem `unknownKey` (found = short description of raw); type parse fail -> `typeMismatch(expected: typeName, found: short)`; enum: parsed box not in cases -> `unknownCase(expected: cases joined ", " (raw string values), found: short)`; record flag: `recordValues(matching:) == nil` -> `typeMismatch` with expected `a list of records (<field names joined ", ">)` or, if duplicate key, `every record to have its own <keyName or "key">` and found `two with <shortMessageDescription of dup>` else short description of raw. Any problems -> throw `rejected(problems sorted by key.rawValue)`; nothing applied. Short description: strings quoted with `\\ \n \r \t` escaped and truncated to 40 chars + `…`; bool `true/false`; arrays `an array of N`; objects `an object with N field(s)`; otherwise Swift description of the number.
- `apply(payload)`: `objectWillChange.send()`; `types = schema.valueTypes`; for each (key, box) in payload.values (dictionary iteration order): `previous = types[key].flatMap { source.box(for: key, as: $0) }` (RAW stored value), `source.setBox(box, key)`, append `(key, previous)` to undo. On a thrown error: replay undo in reverse with `try? setBox(previous, key)`, rethrow. The key whose write threw is not in the undo list.
- QR: `qrCodeString()` = `FlagQRCode.encode(FlagPayload(values: overriddenValues))` (throws `payloadTooLarge`). `copyableQRCode`: nil if no overrides or encode throws, else the string. Code is plain text with prefix `FFQR1:` and no spaces. `qrCodeImage(scale: 10)`: CIQRCodeGenerator, correction level `L`, bytes = UTF-8 of the string, nearest-neighbour scaling. Android: ZXing/`qrcode-kotlin` etc. with ECC level L; test (`QRCodeExportTests`) only checks PNG magic bytes `89 50 4E 47` and size > 100.

### 3.5 Schema reload
- `refreshSchema()`: `guard let reloaded = reloadSchema(), reloaded != schema else { return }`; `objectWillChange.send()`; `schema = reloaded`. So: reloader returning nil keeps the old schema; identical (deep-equal, including `generatedAt`) does nothing and emits NO change; different emits exactly one change. Store built without reloader is unaffected.

### 3.6 Structure
- `sections`: `query = searchText.trim(whitespacesAndNewlines).lowercased()`; `matches(entry)` = query empty OR `key.rawValue.lowercased().contains(query)` OR `description.lowercased().contains(query)`.
  1. Ungrouped: flags with `propertyPath.count == 1` and matching; if non-empty add `FlagSection(path: [], title: nil, pathDescription: "", entries)`.
  2. For each `schema.groups` in order: entries = flags whose `propertyPath.dropLast() == group.propertyPath` (DIRECT children only) and matching; skip if empty (so a group containing only subgroups produces no section; test); section `path = group.propertyPath`, `title = group.description`, `pathDescription` = descriptions of every ancestor-or-self group in order joined by ` › ` (U+203A with spaces).
  `descriptions(forGroupPath: path)`: for depth in `1...max(path.count, 1)`: find `schema.groups.first { propertyPath == path.prefix(depth) }?.description` (missing ancestors skipped; for empty path returns `[]` effectively since prefix(1) of [] is [] which would match a group with empty path, normally none).
  Root section id `""`; group section id `path.joined(".")`.
- `tree`: `FlagTreeNode(schema:)` recomputed each call.
- `entry(for key)`: first with equal key; nil for unknown.

### 3.7 Error reporting and strings (core `ErrorMessages.swift`; `description` == `errorDescription`)
Store methods THROW; most views swallow with `try?`. Errors that surface to the user: Overrides `resetAll`/plist export (alert "Could not do that" with `"\(error)"`), Import sheet (`describe`), QR sheet (`unavailableMessage`). Verbatim:
- `FlagImportError.malformed(r)`: `The document could not be read: <r>.` (reasons: `not a JSON object`, `not a property list dictionary`, `missing formatVersion`, `missing values`)
- `unsupportedFormatVersion(v)`: `The document is format version <v>; this build understands 1. Update whichever app is older.`
- `rejected(problems)` empty: `Nothing was applied, and no problem was recorded.` Non-empty: `Nothing was applied. <n> problem<s>:\n  • <problem>\n  • <problem>\nImport is all or nothing, so no flag was changed.`
- `FlagImportProblem.description`: typeMismatch `<key>: expected <expected or "another type">` + (`, got <found>` if present); unknownCase `<key>: <found or "that value"> is not one of <expected or "this flag's cases">`; unknownKey `<key>: no flag has this key. The document came from a different app, or from a build where the flag was named differently`.
- `FlagSerializationError.nonFiniteNumber(key)`: `'<key>' holds an infinity or a NaN, and JSON can represent neither. Use a finite value, or a sentinel the flag's type already has.`
- `FlagQRCodeError.payloadTooLarge(bytes, limit, count)`: `<count> override<s> need <bytes> characters and a QR code holds <limit>. Reset a few, or export JSON instead.` (note: "need", no comma; `s` omitted when count == 1). `unrecognisedFormat`: `Not a flag code. A flag code starts with "FFQR1:".` `corrupt`: `The code could not be decompressed, which usually means a partial scan. Try again with the whole code in frame.` `imageGenerationFailed`: `Core Image could not render the code.`
- `FlagSchemaError.notPublished`: `No schema has been published. The host app writes one with publishSchema(), so run it at least once — and check both targets declare the same App Group in their entitlements.` `unsupportedFormatVersion(v)`: `The schema is format version <v>; this build understands 1. Update whichever app is older.` `malformed(r)`: `The schema could not be read: <r>.`
- `FlagError.unsupportedValue(key)`: `The source refused the value for '<key>' because it cannot represent it. Property list storage accepts a narrower set of types than a flag can declare.` `noMutableSource`: `No source in the stack can be written to. Add a UserDefaultsSource or a SnapshotSource — a pole built only from read-only sources has nowhere to put an override.`
- `FlagRecordEditingError.duplicateKey`: see 1.9.

### 3.8 Reaction to source changes
Any `source.changes` emission -> main-queue `objectWillChange` (UI recompute). `SnapshotSource.setBox` emits `.keys([key])` only if the stored value actually changed (test relies on a change event for a write from "another process"; first emission within 2 s). UserDefaultsSource skips no-op writes (cross-process broadcast). The Android store should expose a change stream from its source and re-evaluate reads lazily.

## 4. Signals

### 4.1 Delay options (`FlagSignalDelay: TimeInterval raw`, public, CaseIterable)
`instant = 0`, `three = 3`, `five = 5`, `ten = 10` in that order (ascending, distinct). `label`: `Instant`, `3s`, `5s`, `10s` (`Int(rawValue)` + `s`). Default delay `.instant`. Picker is segmented, disabled while a send is pending (`model.pending != nil`).
Delay picker text. Section header `Delay`. Footer: instant -> `Sent the moment you tap. The app has to be running to hear it, and opening this one puts it in the background.`; otherwise -> `Tap a signal, then switch to the app. It fires when the circle completes, by which time the app is in front and listening.`

### 4.2 Countdown (`FlagSignalCountdown: Equatable`, internal)
- Fields: `start: Date`, `duration: TimeInterval`.
- `interval = start...start+duration`.
- `progress(at date) = duration > 0 ? clamp((date - start)/duration, 0, 1) : 1`. At start 0; halfway 0.5; after the delay 1 (even 30 s later); before start 0 (never negative).
- Ring is drawn from the clock via `TimelineView(.animation)`: stroke trimmed 0...progress, 20x20 pt, line width 3, round cap, rotated -90 degrees, with a track ring at 20% opacity. NOTE: "progress" fills as time passes (0 -> 1) in the in-app ring while the Live Activity ring "counts down" (drains). Accessibility label (verbatim): `Sending in <Int(duration)> seconds. Tap to cancel.`

### 4.3 `FlagSignalsModel` (@MainActor, ObservableObject; internal)
State: `delay`, `pending: ErasedSignal?`, `countdown: FlagSignalCountdown?`, `inFlight: ErasedSignal?`, `history: [Attempt]`; `channel: FlagSignalChannel?` (nil if the App Group suite cannot open), `timeout` (default 2 s, view init param), `pendingTask`, `keepAlive` (iOS).
- `isDisabled(signal) = channel == nil || inFlight != nil || (pending != nil && pending != signal)`.
- `tapped(signal)`: if `pending == signal` -> `cancelPending()`; else if `delay == .instant` -> `send(signal)`; else `schedule(signal)`. (Tap on a different signal while pending is impossible because the row is disabled. Tapping while `inFlight` is disabled.)
- `schedule`: `countdown = Countdown(start: now, duration: delay.rawValue)`; `pending = signal`; `keepAlive.begin`; start a task that sleeps `delay` seconds (captured at schedule time), if not cancelled sets `pending = nil; countdown = nil` then `send(signal)`.
- `cancelPending()`: cancel task, `pending = nil`, `countdown = nil`, `keepAlive.end()`. History is untouched. Also invoked `onDisappear` of the root `FlagSignalsView` (leaving the tab cancels a pending send; nested screens do not).
- `send(signal)`: guard channel non-nil; `inFlight = signal`; async: `signal.send(over: channel, timeout:)`; any thrown error -> `handled = false` (the error is NOT shown, only recorded); then `history.insert(Attempt(signal, handled, now), at: 0)`, `history = prefix(5)` (LAST 5, newest first), `inFlight = nil`, `keepAlive.end()`.
- No cancellation of an in-flight send. Only one send at a time. A `send` from the instant path does not call `keepAlive.begin`, but still calls `end()` (harmless).
- `Attempt` (`Identifiable` by fresh UUID): `signal`, `wasHandled`, `at: Date`. `outcome`: `(handled, requiresRestart)`: (true,true) -> `handled — relaunch to see it` (em dash U+2014, lowercase); (true,false) -> `handled`; (false,_) -> `no response`.
- Channel semantic (core): `send(signal, timeout)` writes `{"sequence": n+1, "name": rawValue}` to the shared store, posts a Darwin notification, waits up to `timeout` for the host's acknowledgement (handled sequence >= n+1), else throws `FlagSignalError.notAcknowledged` (message in 3.7: `The host did not confirm it handled the signal in time. It may not be running — iOS will not wake a closed app for another app — or it may not be observing this signal's type.`; `unavailableAppGroup(id)`: `The App Group '<id>' could not be opened. Add it to this target's entitlements, and check it matches the host's exactly.`). On Android the IPC (broadcast/ContentProvider/bound service) is already defined in the Android core module; the UI model needs only `suspend fun send(signal, timeoutMs): Unit` that throws on no-ack.

### 4.4 Presentation of signals
- Screen title `Signals` (inline). Layout: delay picker section; for each non-nested group in order a section (header = group title if non-empty); if any nested groups: section `Groups` with rows `LabeledContent(title) { count }` navigating to a group screen (title = group.title) that repeats the delay picker, the list without header, and the history; then the history section; and if `channel == nil` a final section: `The App Group is unavailable, so there is nowhere to send.`
- Signal row: button; description line; if `requiresRestart` a caption line `Takes effect after a relaunch`; trailing: spinner when `inFlight == signal`; ring when `pending == signal` and countdown present; else paperplane icon.
- Section footer (only for the header-less single flat group, i.e. title empty): `model.pending == nil ? "Signals carry no payload. State belongs in flags, which you can already edit." : "Tap again to cancel."`.
- History section `Recent`: each row: label = description + time caption `attempt.at.formatted(date: .omitted, time: .standard)` (locale short time with seconds), value = `outcome` coloured green when handled else orange, right aligned. Shown only when history non-empty.
- Single-type convenience `FlagSignalsView(Type, appGroup:, timeout: 2)` = one group titled `""` with `display: .flat`.
- Live Activity strings: `Sending in <timer>`; the activity's `signal` attribute is the signal's description.

## 6. iOS-only things and suggested Android mapping (one line each)

- App Group (`UserDefaults(suiteName:)`, container URL, entitlements) -> whatever M2 chose (ContentProvider/shared file/`Intent` + package visibility); the `FlagEditingStore(appGroup:)` init becomes `FlagEditingStore.open(hostPackage)` returning a `Result`/throwing the "host never run / not declared" error.
- Darwin notifications for signals and acks -> bound service/broadcast with explicit ack (already in Android core per M2); UI only needs a suspend `send(timeout)`.
- `didBecomeActive` refresh -> `ProcessLifecycleOwner` ON_START / Activity ON_RESUME calling `refreshSchema()` and retrying a failed load.
- Combine `ObservableObject`/`objectWillChange`/`@Published searchText` -> `StateFlow`/Compose `mutableStateOf`; recompute sections/values from the source on each read, bump a version on source change and on mutations.
- SwiftUI Form/List/NavigationStack/TabView/sheets/alerts -> Compose Material 3 (LazyColumn, NavHost, NavigationBar, ModalBottomSheet/Dialog, AlertDialog).
- SF Symbols and `.fill` selected variant -> Material icons filled/outlined pair; names are only identifiers (`dial.medium`, `flag`, `paperplane`, `square.stack.3d.up`, `qrcode`, `doc.on.doc`, `arrow.uturn.backward`, `flag.slash`).
- `UIPasteboard`/`NSPasteboard` -> `ClipboardManager` (text); image copy -> ClipData with FileProvider URI.
- `ShareLink` (JSON text, PNG file) -> `Intent.ACTION_SEND` (text/plain; image/png via FileProvider); "Copy property list" has no Android analogue (drop or export same JSON).
- Property-list export/import format (`FlagPayloadFormat.plist`) -> drop or leave unsupported; JSON is the interchange format (QR uses JSON).
- CoreImage `CIQRCodeGenerator` (level L) and Core Graphics PNG -> ZXing `QRCodeWriter` with `ErrorCorrectionLevel.L` plus `Bitmap.compress(PNG)`; no scanning UI on iOS either (import takes pasted text).
- `Compression` framework `COMPRESSION_ZLIB` (QR payload) -> `java.util.zip.Deflater`/`Inflater`; verify raw-vs-zlib-header compatibility against shared fixtures before trusting round trips with iOS-made codes.
- ActivityKit Live Activity/Dynamic Island + UIKit background task (`FlagSignalKeepAlive`) -> optional foreground-service notification with chronometer countdown; acceptable v1: keep the countdown in a ViewModel and cancel on dispose.
- `ISO8601DateFormatter(.withInternetDateTime)` -> `java.time.OffsetDateTime`/`Instant` formatting with second precision and `Z`; reject fractional seconds on parse to stay strict.
- `JSONSerialization` options `sortedKeys`/`withoutEscapingSlashes` -> kotlinx.serialization/org.json with a custom sorted writer (must be byte-stable for `storageIdentity`, record text, and `displayString` expectations like `{"a":1,"b":2}`).
- NSNumber bool-vs-number detection (`isBooleanValue`) -> JSON parser that preserves boolean vs number token types (kotlinx `JsonPrimitive.isString`/`booleanOrNull`).
- Swift `Double`/`Float` description formatting -> reproduce shortest round-trip ("1.0", "3.5", "1e-05"); or document divergence from Kotlin's `1.0E-5`.
- Swift `Int` (64-bit) -> Kotlin `Long`; `Float` -> `Float`.
- `precondition` crashes (duplicate tab ids, duplicate signal ids across groups, non-finite in `FlagValueBox.records`) -> `require(...)` throwing `IllegalArgumentException` at construction.
- `NavigationLink` summary rows / swipe actions (Duplicate leading swipe, delete trailing) / `EditButton` + drag move -> Compose `SwipeToDismissBox` or overflow menu, reorder via up/down buttons or `reorderable` library.
- Text field focus-loss commit (`onChange(of: isFocused)`) -> `onFocusChanged` plus IME action Done; keep the same "revert + warning icon on parse failure" behaviour.
- `.searchable` -> `SearchBar`/`TextField` bound to `searchText`.
- `Date` picker (date+time, no seconds control) -> Material3 `DatePicker` + `TimePicker` pair; note writing seconds=0 changes the stored value precision vs. text entry.
- Localised time `.formatted(date: .omitted, time: .standard)` for history rows -> `DateFormat.getTimeFormat(context)` or `DateTimeFormatter.ofLocalizedTime(FormatStyle.MEDIUM)`.
- macOS vs iOS gating (`#if os`) -> irrelevant on Android.

### Caveats worth flagging in the plan
1. Duplicate action on a keyed record list: the iOS Duplicate swipe inserts an exact copy; if the shape has a key the subsequent `setRecords` throws `FlagRecordEditingError.duplicateKey` and `try?` swallows it, so nothing happens and nothing is shown. Tests only cover Duplicate for a keyless shape. A better Android behaviour is to run the copy through `emptyRecord`-style key suffixing, or show the error; this is a pre-existing iOS defect to mention, not copy blindly.
2. `setValue`/`reset` failures are silently swallowed by nearly every iOS view (`try?`). Android should surface at least a snackbar.
3. `isOptional` and `decodedName` on `FlagRecordField` are ignored by the iOS editor; optional fields cannot be cleared. Decide whether M3 includes a clear affordance.
4. `FlagSchema.==` includes `generatedAt`, so a host republish with a fresh timestamp but identical flags triggers a refresh and view invalidation (still correct, just not "free"). Choose equality deliberately on Android (data class equality including `generatedAt` to match tests; tests only compare structurally identical schemas).
5. Parsing of `Double("inf")`/`nan` is accepted and later makes JSON export throw; consider rejecting non-finite on Android parse (deliberate divergence, needs a test).
6. iOS 17+ `URL(string:)` is lenient; only the empty-string rejection is test-asserted.
7. `emptyBox` for `.date` is `Date()` (now) and for `array` is a one-element array; tests only assert url non-nil and the listed scalars. Keep behaviour for compatibility but beware time-dependent tests.
